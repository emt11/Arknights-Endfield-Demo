> 当前活动工程仅包含 P1，更新于 2026-11-17

UI 使用实施计划前的原有布局和样式，属性数据继续由 P1 的 `GameUIController` / `CharacterStatsPanelUI` 绑定；本次恢复只涉及场景中的 UI 配置，没有改写运行时显示逻辑。

先读 [战斗系统完整实现文档](战斗系统完整实现文档.md) 的范围、操作与验证，再从下面入口阅读源码。完整的 P2～P5 设计仍在 [仿终末地完整实现方案](仿终末地完整实现方案.md)；之前写出的后续代码与原始混合版本保存在 [备份目录](../Backups/CombatBeforeP1Only_2026-11-17/README.md)，当前不会编译或运行。

## 1. 阅读顺序

| 顺序 | 源码入口 | 重点 |
|---|---|---|
| 1 | `Assets/Scripts/Runtime/Input/GameInputManager.cs`、`Character/PlayerController.cs` | 帧输入快照、捕获/暂停、相机方向转移动意图、攻击请求 |
| 2 | `Combat/CombatSimulation.cs`、`Combat/CombatRulesDefinition.cs` | 每帧预算、每步顺序、单次移动、命中排序、延后结果 |
| 3 | `Combat/Input/CombatInputBuffer.cs` | 输入帧去重、序号、过期和成功后消费 |
| 4 | `Character/CharacterDefinition.cs`、`Character/Combatant.cs`、`Character/Stat/` | 三属性和普攻共享配置、角色状态、生命与内部死亡 |
| 5 | `Combat/Actions/ActionDefinition.cs`、`ActionRuntime.cs`、`ActionController.cs` | 定义与实例、执行 ID、点/窗口时序、自然结束和取消清理 |
| 6 | `Combat/Actions/ComboController.cs` | 普攻数组、推进点、取消窗口和输入缓存共同决定接段 |
| 7 | `Combat/Animation/AnimationPlayer.cs`、`AnimatorRootMotion.cs`、`Character/Movement/` | Playables 手动求值、根增量与 Motor 统一移动 |
| 8 | `Combat/Weapons/WeaponController.cs`、`Combat/HitDetection/`、`Combat/Resolution/CombatResolver.cs` | 指定骨骼挂载、武器前后姿态、窗口交集与分段查询、两层去重、伤害和死亡顺序 |
| 9 | `Combat/TargetingController.cs`、`Combat/Animation/MotionWarping.cs`、`RootMotionDefinition.cs` | 辅助选敌、窗口锁定、根轨迹修正、碰撞后停止贴近 |
| 10 | `Presentation/CombatFeedbackPlayer.cs`、`UI/CombatHUD.cs`、`UI/GameUIController.cs` | 池化音效/粒子与局部事件，木桩/连段 HUD 和三属性面板 |
| 11 | `Assets/Scripts/Editor/Combat/` | Inspector、Timeline 轨道编辑、隔离预览和实际 Avatar 根轨迹烘焙 |

表中从第二列 `Character/`、`Combat/` 等开头的路径均相对于 `Assets/Scripts/Runtime/`。框架入口只有当前所需职责，没有通用 NotifyRunner、全局事件总线、技能提交层或行为树运行时。

项目自定义 SO 资源统一位于 `Assets/ScriptObjects/`：`Characters/` 保存角色配置，`Combat/Actions/`、`Combat/RootMotion/`、`Combat/Rules/` 保存战斗定义，`Presentation/` 保存表现配置。Timeline 验证资源位于 `Tests/Editor/TimelineFixture.asset`，对应的验证代码仍在 `Assets/Tests/Editor/`。

代码字段使用 camelCase，属性和方法使用 PascalCase，例如 `definition.hitWindows`、`runtime.LocalTime`。现有资产已直接更新字段名，不依赖旧名称映射。`GameInputManager.Awake` 顺序建立输入与 UI 绑定；`CharacterMotor.PlanLocomotion` 完成速度与转向规划，`ApplyMovement` 连续处理重力、移动提交、碰撞状态及实际位移记录。

移动状态只保留 `Character/Movement/LocomotionStateId.cs` 枚举，Idle/Walk/Run 选择直接在 Motor 中完成。通知点为 `ComboAdvancePoint`、`AudioPoint`、`EffectPoint`，通过托管引用内嵌在动作资产中；`ActionPointEditor` 为 Timeline 与 Inspector 提供共同的添加、独立复制及排序操作。

## 2. 一次攻击的真实调用链

`GameInputManager.Update` → `PlayerController.Update` → `CombatSimulation.QueueAttack` → `CombatInputBuffer`

战斗步入口：`PlayerController.SubmitAction` → `ComboController.TryAttack` → 选目标 → `ActionController.TryStart` 检查存活与取消条件 → 创建 `ActionRuntime` → 替换旧动作并播放动画 → 消费输入 → 处理零时刻通知。

动作和根轨迹配置直接读取，不在初始化或每次起手时扫描校验。根轨迹依赖签名只用于编辑器提示重新烘焙；窗口范围、引用和模型匹配由开发者维护。

根轨迹直接引用已有 `Phoebe.fbx`，签名包含采样率。预览循环在编辑器 `ActionPreview` 内，按实际动作倍率、战斗步长与身体半径调用共享求值；`TargetingController.IsWithinAssistance` 提供共用的距离、角度及高度判断。

随后每步：`WeaponController.CaptureStart` → `ActionController.Advance` → `Motor.PlanLocomotion` → `AnimationPlayer.Evaluate` → 根轨迹/扭曲计算 → `Motor.ApplyRotation/ApplyMovement` → `WeaponController.CaptureEnd` → `ProcessEvents` → `Physics.SyncTransforms` → `HitDetection.Collect` → 排序 → `CombatResolver.Resolve` → `FinishAtEnd` → 发布结果。

`WeaponController.Awake` 把武器 Prefab 实例化到序列化的骨骼挂点，建立 `id → Hitbox` 缓存。`HitWindow.hitboxIds` 选择检测体，`group` 控制一次动作的伤害去重；几何配置在武器 Prefab 上。`HitDetection.Collect` 截取有效窗口后调用 `Hitbox.Query`，后者统一处理姿态插值、分段物理查询、缓冲扩容与接触点计算。返回的 `HitboxContact` 只包含碰撞体与接触点；目标筛选、遮挡、批次去重和请求收集在 `Collect` 中顺序完成，扣血仍由 `CombatResolver` 负责。Timeline 预览复用同一武器配置和几何计算，不执行物理查询。

目标使用普通 Collider：`targetMask` 筛选 `HitTarget` 层，`Collider.GetComponentInParent<Combatant>()` 查找角色。当前没有 Hurtbox 组件或 Owner 缓存；死亡只清理当前动作，检测与结算依据存活状态排除死亡角色，不遍历关闭受击组件。

结束或取消：清空 `Current`，标记原 Runtime 已结束，归还其跟随效果与持续窗口句柄，动画淡出，记录结束原因。旧执行 ID 不会取消新的动作。

停用协调从 `Combatant.InterruptAction`、Motor/AnimationPlayer 的 `OnDisable` 和模拟器的参与条件阅读。玩家控制停用只清理输入；动作组件停用仍允许普通移动；动画或 Motor 停用中断动作并停止相关模拟。`useRootMotion` 统一控制动作根平移、根旋转与扭曲，关闭后仍保留骨骼挥击和碰撞重力。

## 3. 时间与通知的调试位置

- 输入没有触发：先看 `GameplayCaptured`、当前帧快照及缓存序号；第一次点击只捕获控制，暂停会清空攻击缓存
- 无法接段：同时检查 `ComboAdvanced`、当前攻击取消窗口、缓存是否过期；不要只看动画是否仍在播放
- 点通知重复/缺失：看 `ActionRuntime.NextPoint`、`LocalTime` 和动作执行 ID
- 命中不生效：依次看 WeaponController 挂点/Prefab、Hitbox ID 与有效世界尺度、窗口交集、真实刀刃轨迹、targetMask/worldMask、Collider 父级 Combatant、阵营、遮挡、runtime.hits、来源/目标当前状态
- 动画与移动不一致：看 `ClipTime`、`PreviousTime/LocalTime`、动画根增量和 Motor 的请求/实际位移；角色根位置只由 Motor 提交
- 扭曲异常：看选中目标、`WarpState`、源烘焙签名、窗口是否覆盖整个前进段、站位安全检查与 `ObserveCollision`
- UI 结果晚于扣血：这是步末发布设计；内部生命和死亡清理先完成，外部订阅之后执行

窗口不是普通每帧“当前时间在里面就触发”的单一模型：命中读取经过区间，取消读取提交时刻，效果记录进入状态，扭曲按窗口片段求增量。具体契约见实现文档第 4 节。

## 4. 运行与编辑验证入口

`Assets/Tests/Scenes/` 保留动画技术验证，以及 Entry、Action、Hit、Combo、Scene、Warp 六个 P1 场景。各场景中的 `Combat*Probe` 使用已有最小断言检查关键路径；正常输入场景需要 Game View 获取焦点。

`Endfield.EditorValidation.CombatTimelineValidation.Run()` 检查实际 IMGUI 拖动、吸附、Undo/Redo、保存重导入；`CombatWarpEditorValidation.Run()` 检查烘焙签名、预览、目标拖动和释放。调用会写入 `Logs/`，时间与结果以本次日志为准。

旧批处理类可能重建配置或退出 Unity，只作为独立批处理工具保留。不要在当前工作编辑器调用 `CombatEntryBatch`、`CombatValidationBatch` 的批处理方法，或用早期配置生成器重置已经调好的动作资产。

当前可游玩入口为 `CombatDemo`，没有旧的四人遭遇或自动通关驱动。测试木桩死亡后重新进入 Play Mode 即可恢复。实际验证结果及未覆盖边界集中在实现文档第 8 节。
