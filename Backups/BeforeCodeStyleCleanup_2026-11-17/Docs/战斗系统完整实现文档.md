## 2. 开始测试

1. 打开 `Assets/Scenes/CombatDemo.unity`，进入 Play Mode，点击 Game View 捕获鼠标；首次点击用于捕获控制
2. `WASD` 移动、`Shift` 跑步、鼠标转镜头；靠近正前方木桩，左键攻击
3. 接段窗口内再次点击可接第二、第三段，略早输入在 0.2 秒缓存内可等待窗口；未成功接段则自然结束
4. `C` 打开三属性面板；面板打开期间战斗暂停，`Esc` 关闭并恢复之前的控制状态
5. 普通游戏状态按 `Esc` 释放鼠标并暂停战斗，再点击 Game View 恢复
6. 木桩死亡后显示“已击破”、禁用 Hurtbox；重新测试时退出并重新进入 Play Mode

P1 没有重开、技能、闪避、切人或锁定按键。玩家当前攻击 100、最大生命 1000、防御 20；木桩最大生命 1000、防御 50。木桩没有 AI 和攻击动作。

## 3. 模块与状态归属

| 模块 | 当前职责 |
|---|---|
| `GameInputManager` / `PlayerController` | 每渲染帧读取输入与镜头方向；提供移动意图、攻击请求；在战斗步入口消费成功请求 |
| `CombatSimulation` / `CombatRulesDefinition` | 时间预算、战斗步顺序、单位编号、命中排序、结果延后发布；规则资产保存步长、缓存和检测层 |
| `CharacterDefinition` / `Combatant` | 共享三属性与普攻顺序配置；角色实例持有 Stats、Health、Motor、Animation、Actions、Combo、Targeting |
| `ActionDefinition` | 共享动画片段、裁剪区间、倍率、混合、点通知、命中/取消/持续效果/扭曲窗口 |
| `ActionRuntime` | 每次执行的 ID、目标、前后时间、通知游标、命中集合、效果句柄及扭曲状态 |
| `ActionController` / `ComboController` | 当前动作提交/推进/退出与清理；依据普攻数组、推进点和取消窗口决定下一段 |
| `AnimationPlayer` / `AnimatorRootMotion` | 手动 PlayableGraph 求值，移动/新旧动作混合，收集根增量；不直接移动角色根对象 |
| `CharacterMotor` | 规划普通移动；统一提交旋转、水平位移、重力和碰撞，记录实际移动结果 |
| `HitDetection` / `Hurtbox` | 窗口与时间段求交、球形重叠/扫掠、阵营和墙体过滤，产生 HitRequest |
| `CombatResolver` / `CharacterHealth` | 最终去重、伤害与扣血、内部死亡清理；对外生命/命中结果延后通知 |
| `TargetingController` / `MotionWarping` | 起手选近距可辅助目标，按窗口修正烘焙轨迹，接受 Motor 阻挡反馈 |
| `CombatFeedbackPlayer` / `CombatHUD` | 复用原有池化音效与粒子；显示命中和木桩生命，没有全局事件总线 |

项目自行编写的 SO 类型统一使用 `Definition` 后缀。保留旧资源实例名，例如 `PlayerCharacterAsset.asset`，不因此更换资源 GUID。

动作配置由开发者维护，运行时直接使用。`ActionDefinition` 只描述数据，初始化、起手和预览前均不执行全量配置校验，也不预扫描窗口、挂点或模型匹配情况。`TryStart` 在一个方法内完成业务条件判断、创建运行时、替换旧动作、播放和记录结果；死亡、取消条件、目标失效及执行 ID 检查仍按实际状态执行。

## 4. 时间步与完整执行流程

每渲染帧按未缩放时间计算：先处理暂停/剩余顿帧，再乘战斗倍率；最大子步为 1/60 秒，每帧最多 4 步。超预算部分直接截断，下一帧不追赶。`Now` 仅累计实际执行的步长。顿帧目前只是时间入口能力，P1 未接入自动命中顿帧表现。

每个战斗步按以下顺序执行：

1. 清除过期攻击缓存，执行上一步结果回调提出的取消请求
2. 尝试提交攻击或移动取消；成功攻击先消费输入，再处理动作零时刻点
3. 推进动作前后时间，规划普通移动，手动求值动画
4. 根据普通移动、根增量或扭曲结果计算位移，经 Motor 每步统一提交一次
5. 累加战斗时钟，处理经过的点通知和持续效果窗口
6. 同步物理 Transform；收集命中请求，按来源 ID、执行 ID、命中组、目标 ID 排序
7. 逐条结算、立即做内部死亡清理；处理动作自然结束
8. 最后发布动作、生命、属性与命中结果；发布期间拒绝新动作提交，取消请求延到下一步

没有通用 `ActionTimeline + NotifyRunner` 框架。动画只负责姿态求值，玩法通知读取同一动作数据：

- 点通知：按时间排序，通过 `NextPoint` 游标处理所有 `Time <= LocalTime` 的未处理点；每次执行只触发一次，包含零时刻与裁剪结束点
- 命中窗口：取 `[PreviousTime, LocalTime]` 与窗口的有效交集；对实际位移段插值后做重叠和扫掠，完整跨过短窗口也不会漏掉
- 取消窗口：提交请求时检查当前动作时间是否位于 `[Start, End)`，不以本步曾经过窗口作为持续许可
- 持续效果窗口：逐窗口判断进入/退出；同一步跨过整个窗口时先进入再归还；取消、死亡、停用均归还该动作自己的句柄
- 扭曲窗口：对经过的窗口片段求源轨迹增量与有限修正，不用渲染动画事件决定玩法时序

三段普攻采用顺序数组。连段推进点表示允许推进的阶段已到达，攻击取消窗口表示当前能否替换动作；两者同时满足才接下一段。攻击可以空挥接段，末段不会因已消费的输入自动开始新一轮。

## 5. 命中、生命与反馈

P1 使用角色局部偏移的球形判定，扫掠依据角色实际移动和旋转；尚无武器骨骼轨迹、其他形状或弹体。

检测阶段先做单批次去重，结算阶段以“当前执行 ID 对应的 Runtime + 命中组 + 目标 ID”记录已结算目标。多个 Hurtbox、连续帧或同组窗口对同一目标只结算一次。动作取消、来源死亡、目标死亡/停用会令后续请求失效。

伤害公式：`max(0, Attack × DamageMultiplier) × K / (K + max(0, Defense))`，当前 `K = 100`。不包含暴击、元素抗性、护盾、异常或资源奖励。

生命改变立即更新内部状态；死亡立即取消当前动作并关闭 Hurtbox，再延后发送 UI 等外部通知。已有生命治疗方法属于原有基础能力，P1 没有治疗技能系统。

当前主场景以 HUD 显示命中伤害和木桩生命。动作配置支持音效点、粒子点及持续效果窗口，复用现有对象池；它们不是自动生成的全套命中特效配置。

## 6. 运动扭曲与动作编辑

三个普攻均保留对应根轨迹资产和扭曲配置。使用 `PhoebeRootModel.prefab` 的实际 Avatar 与尺度、60 Hz 顺序采样烘焙根轨迹；纯预览模型不引用战斗动作。源片段、模型或尺度改变后要重新烘焙，根轨迹 Inspector 保留过期提示；运行时不比较签名或据此拒绝起手。

起手辅助范围为存活敌人、距离不超过 3.5 米、前方 60 度、高差不超过 0.5 米，且视线无遮挡。窗口进入时锁定本窗口目标站位；不会每帧追踪移动目标。目标失效后关闭该窗口修正，后续按原始源增量继续。

默认额外停止间距 0.15 米、最大贴近 2 米、额外延伸 1 米、最大速度 8 米/秒、修正角 60 度、角速度 720 度/秒。玩家半径 0.3 米、木桩半径 0.5 米；受到限制时允许无法到达理想位置。碰墙后停止本窗口的贴近修正，不累积被阻挡的距离等待补偿。

第一段扭曲覆盖主要前进区间 `[0, 2.633333)`；第二、第三段分别配置自己的前进段，回撤部分保留原始轨迹。保留这些 P1 站位配置，避免缩回旧的极短窗口后，窗口之外的根运动再次穿过目标。

双击动作资产或打开 `Window/Endfield/Action Timeline`：

1. 选择动作与预览角色，播放、逐帧或拖动游标查看姿态和轨迹
2. 拖动点通知、窗口两端或中部；按需开启帧吸附，关闭后可保存非整帧时间
3. 在详细字段中编辑配置；Undo/Redo 支持撤销/重做
4. 修改扭曲窗口和模拟目标，查看源轨迹与扭曲轨迹；需要时更新根轨迹烘焙
5. 点击“保存”，运行时直接读取同一份资产

时间轴拖拽保留范围限制、点通知排序和帧吸附；详细字段允许直接输入，由开发者维护配置关系，不另设全量保存校验。编辑器是隔离 Preview Scene，不执行真实伤害；关闭或预览失败时释放预览对象，预览异常不阻止保存。预览正确不等于战斗碰撞与动画衔接已验收。
