## 2. 一次攻击的真实调用链

`GameInputManager.Update` → `PlayerController.Update` → `CombatSimulation.QueueAttack` → `CombatInputBuffer`

战斗步入口：`PlayerController.SubmitAction` → `ComboController.TryAttack` → 选目标 → `ActionController.TryStart` 检查存活与取消条件 → 创建 `ActionRuntime` → 替换旧动作并播放动画 → 消费输入 → 处理零时刻通知。

动作和根轨迹配置直接读取，不在初始化或每次起手时扫描校验。根轨迹依赖签名只用于编辑器提示重新烘焙；窗口范围、引用和模型匹配由开发者维护。

随后每步：`ActionController.Advance` → `Motor.PlanLocomotion` → `AnimationPlayer.Evaluate` → 根轨迹/扭曲计算 → `Motor.ApplyRotation/ApplyMovement` → `ProcessEvents` → `Physics.SyncTransforms` → `HitDetection.Collect` → 排序 → `CombatResolver.Resolve` → `FinishAtEnd` → 发布结果。

结束或取消：清空 `Current`，标记原 Runtime 已结束，归还其跟随效果与持续窗口句柄，动画淡出，记录结束原因。旧执行 ID 不会取消新的动作。

## 3. 时间与通知的调试位置

- 输入没有触发：先看 `GameplayCaptured`、当前帧快照及缓存序号；第一次点击只捕获控制，暂停会清空攻击缓存
- 无法接段：同时检查 `ComboAdvanced`、当前攻击取消窗口、缓存是否过期；不要只看动画是否仍在播放
- 点通知重复/缺失：看 `ActionRuntime.NextPoint`、`LocalTime` 和动作执行 ID
- 命中不生效：依次看窗口交集、Hurtbox/World Mask、阵营、遮挡、Runtime.Hits、来源/目标当前状态
- 动画与移动不一致：看 `ClipTime`、`PreviousTime/LocalTime`、动画根增量和 Motor 的请求/实际位移；角色根位置只由 Motor 提交
- 扭曲异常：看选中目标、`WarpState`、源烘焙签名、窗口是否覆盖整个前进段、站位安全检查与 `ObserveCollision`
- UI 结果晚于扣血：这是步末发布设计；内部生命和死亡清理先完成，外部订阅之后执行

窗口不是普通每帧“当前时间在里面就触发”的单一模型：命中读取经过区间，取消读取提交时刻，效果记录进入状态，扭曲按窗口片段求增量。具体契约见实现文档第 4 节。

## 4. 运行与编辑验证入口

`Assets/Tests/Scenes/` 保留动画技术验证，以及 Entry、Action、Hit、Combo、Scene、Warp 六个 P1 场景。各场景中的 `Combat*Probe` 使用已有最小断言检查关键路径；正常输入场景需要 Game View 获取焦点。

`Endfield.EditorValidation.CombatTimelineValidation.Run()` 检查实际 IMGUI 拖动、吸附、Undo/Redo、保存重导入；`CombatWarpEditorValidation.Run()` 检查烘焙签名、预览、目标拖动和释放。调用会写入 `Logs/`，时间与结果以本次日志为准。

旧批处理类可能重建配置或退出 Unity，只作为独立批处理工具保留。不要在当前工作编辑器调用 `CombatEntryBatch`、`CombatValidationBatch` 的批处理方法，或用早期配置生成器重置已经调好的动作资产。

当前可游玩入口为 `CombatDemo`，没有旧的四人遭遇或自动通关驱动。测试木桩死亡后重新进入 Play Mode 即可恢复。实际验证结果及未覆盖边界集中在实现文档第 8 节。
