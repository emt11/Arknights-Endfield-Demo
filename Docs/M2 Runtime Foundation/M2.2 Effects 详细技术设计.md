# M2.2 Effects 持续效果详细技术设计 V1.1

**已实现 · Unity 定向验收通过**　两次施加同一个攻击增益会产生两个独立实例，先到期的实例只撤销自己的词条，刷新其中一个实例时沿用原句柄 · [M2 阶段总览](./M2%20Runtime%20Foundation%20开发设计.md)

## 1. 配置与数据归属

| 内容 | 所有者 | 首版规则 |
| --- | --- | --- |
| 时长、属性词条、伤害加成和周期动作 | 共享的 `EffectProfile` 资产 | `durationSeconds` 为正的有限战斗秒数，`modifiers` 按 Stats 现有的属性、操作、值、优先级填写<br>可选 `outgoingDamageBonus` 用比例表示，可选周期动作填写正间隔和单次量 |
| 生效中的实例 | 每个目标的 `EffectController` | 保存模板、施加者、实例序号、到期时刻与下一次周期时刻<br>施加者取本次施加方的只读属性面板引用，自身效果传自身面板，目标由控制器实例确定 |
| 角色最终属性 | 目标的 `StatSet` | 每个实例独占 `new SourceID("Effect", sequence)`，一次提交该效果的整组 `StatModifier`，目标内序号从 1 递增<br>角色构筑继续使用独立来源 · [StatModifier 与 SourceID](../../Assets/Scripts/Runtime/Stats/Modifiers/StatModifier.cs) · [StatSet](../../Assets/Scripts/Runtime/Stats/Runtime/StatSet.cs) |
| 限时伤害修正 | 效果实例 | 首版支持“造成伤害 +X%”这一种 `DamageModifier`，叠加时求所有活跃实例的比例之和，结束时只撤去该实例的贡献<br>Damage 在出招时复制这个合计值，已有面板的 ATK 百分比仍只在 Stats 内计算 |

Inspector 与运行时共用 `StatModifier`。效果控制器直接把模板的词条数组传给 `StatSet.ReplaceSource`，由 Stats 校验并复制到该来源，覆盖冲突、派生计算与最终范围沿用现有规则

只提供定时信号的效果可以配置空词条，比如 Status 的冻结计时

## 2. 调用入口与生效顺序

运行时代码位于 `Assets/Scripts/Runtime/Effects/`，命名空间为 `Endfield.Effects`

角色逻辑根的 `CharacterEffects.Awake` 按顺序 −40 执行，从同节点取已初始化的属性面板与资源容器，创建并公开 `EffectController`，订阅周期通知，退出战斗时释放订阅 · [角色资源组件的顺序 −50](../../Assets/Scripts/Runtime/Resources/Character/CharacterResources.cs)

`Start` 在本场景根节点查找 `BattleTimeDriver` 并订阅 `Clock.SubscribeBattleStep`，`CombatDemo` 中驱动位于 `Combat Session`。每次通知以 `TimeStep.Delta` 调用一次 `Advance`，请勿再由角色的 `Update` 推进。角色禁用保留订阅并继续参加战斗计时，销毁时先解除时钟与周期订阅，再撤销仍生效的来源。独立测试场景可由夹具直接推进控制器 · [场景时钟](../M1/M1.4%20CombatContracts%20与%20Timing%20详细技术设计.md)

| 入口 | 调用方能观察到的结果 |
| --- | --- |
| `TryApply(profile, instigator, out handle, out error)` | 每次创建独立实例，句柄包含目标控制器和实例序号<br>先检查配置并提交属性来源，成功后登记计时与伤害修正，失败时返回原始错误，旧实例与面板保留 |
| `TryRefresh(handle)` | 只对所属控制器的活跃实例生效，到期时刻设为“当前战斗时刻 + 模板时长”，保留已经走过的周期进度<br>希望同次施加仅刷新时，由施加方保留并传回原句柄 |
| `TryRemove(handle, out error)`、`IsActive(handle)` | 移除指定实例并撤销其来源，手动移除和到期共用结束路径<br>过期或其他目标的句柄无法影响本目标 |
| `OutgoingDamageBonus`、`Advance(double battleDeltaSeconds)` | 前者读取本角色全部活跃的出伤加成，后者推进非负有限秒数，传 0 时所有时点保持原值 |
| `SubscribePulse(listener)`、`SubscribeEnded(listener)` | 用 Common 的实例通知器订阅，返回可释放的订阅句柄<br>周期通知携带实例句柄、施加者、周期动作与量，结束通知携带已失效的句柄 · [公共通知器](../../Assets/Scripts/Runtime/Common/ChangeNotifier.cs) |

创建和撤销都以 `StatWriteResult.Success` 为准

若移除来源失败，`TryRemove` 返回 false 并保留实例、伤害修正和 Stats 错误。`Advance` 遇到到期撤销失败时继续结算本步其他实例，随后抛出带原始原因的 `InvalidOperationException`。下一次正步长重试撤销，已经发出的周期不会重播

Stats 自身会在写入返回前同步通知面板订阅者，效果的完整状态在效果操作返回后读取

## 3. 计时与周期边界

1. 控制器使用战斗秒数累计时刻，首次周期在 `施加时刻 + interval`<br>一次跨过多个周期时按时间先后补齐，截止时刻包含到期点
2. 同一时刻先结算到点的周期，再移除到期效果，同类事件按实例序号处理<br>手动移除只取消未来周期，刷新保持下一次周期的原定时刻
3. 举例，祀初始终结技能量为 30<br>一个持续 3 秒、每秒恢复 5 的效果在第 1、2、3 秒各触发一次，第三次后立即结束<br>角色端周期订阅者调用该目标的 `RestoreUltimate(5)`，能量依次为 35、40、45 · [祀资源配置](../../Assets/ScriptObjects/CombatResources/Si.asset) · [能量恢复入口](../../Assets/Scripts/Runtime/Resources/Character/CharacterResourceContainer.cs)
4. 每个目标每个战斗步只调用一次 `Advance`，定向测试直接传入步长，正式循环从统一驱动取得战斗增量<br>角色切换操控权时保留控制器，退出战斗时释放订阅并撤销仍写在存活面板上的实例来源

周期到点时 `EffectController` 发布动作与单次量，角色端的 `CharacterEffects` 订阅者调用资源容器的 `RestoreUltimate`，纯计时用例可以直接推进控制器

回调中需要新增或刷新同一控制器的效果时，由调用方在本次推进返回后提交

### 实际验收记录

Unity 6000.3.28f1 中，3 项 `EffectControllerTests`、1 项原有构筑兼容用例及 `CombatDemoDrivesCharacterEffectsAcrossPauseAndCharacterSwitch` 均通过。木剑与双增益得到 710.24 → 750.24 → 730.24 → 710.24，切换角色并跨过暂停、半速后，祀在第 3 个战斗秒收到最后一次回能，最终能量 45。Stats 通知期间拒绝撤销后，下一步成功撤销，累计 3 次周期
