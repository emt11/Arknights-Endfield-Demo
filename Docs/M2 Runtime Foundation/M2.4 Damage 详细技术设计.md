# Damage 伤害结算设计草案 V1.1（M6 连招阶段实施）

**排期已确定，公式与参数待评审**　Damage 随 M6 首条连招一起实现与验收。文档沿用原 M2.4 文件名。M2 交付 Pooling、Effects、Status，M6 贯通选段、动作、武器轨迹、去重命中与目标结算，接口和实施文件以 [M6 战斗执行详设](../M6%20Combat%20Execution/M6%20战斗执行详细技术设计.md) 为准 · [阶段路线](../仿终末地战斗系统设计方案.md#61-总体路线)

**配置归属已确定**　Damage 定义普通的 `[Serializable] struct DamageSpec`。每个攻击段在所属 Action 的 Inspector 中直接填写伤害参数，与本段的命中窗口一并保存。Combos 选择并提交动作，HitDetection 确认该窗口命中了谁，Damage 使用该段参数结算。原案的独立 `DamageProfile` ScriptableObject 和配套练习攻击资产取消

## 1. 三个取值时点

| 时点 | 谁持有数据 | 具体字段 |
| --- | --- | --- |
| 攻击提交 | Damage 创建只读 `AttackSnapshot`，调用方随该次攻击保存 | 从 `IReadOnlyStatSet` 复制 `ATK`、`CritRate`、`CritDamage` 和调用方提供的出伤加成合计值<br>用于标记施加方的引用与用于计算的数值分开，同一攻击的多段命中可复用数值副本 · [Stats 只读接口](../../Assets/Scripts/Runtime/Stats/Runtime/StatReadModels.cs) |
| 每段确认命中 | Action 攻击段持有 `DamageSpec`，目标持有 `DamageReceiver` | 用已确认的命中窗口找到对应攻击段，取该段配置的伤害类型、倍率、失衡值与附着。现场读取目标 DEF、对应抗性和物理承伤倍率，为本次结算取一份暴击抽样值 |
| 结算提交 | Resources 持有当前生命，Status 持有状态，Damage 返回 `DamageResult` | 计算明细保留各乘数，实际扣血与溢出直接取 `HealthLossResult`<br>已有血条自然收到资源通知 · [实际扣血入口](../../Assets/Scripts/Runtime/Resources/Character/CharacterResourceContainer.cs) · [现有血条](../../Assets/Scripts/Runtime/UI/HealthHud.cs) |

M6 计划把结算代码放在 `Assets/Scripts/Runtime/Combat/Damage/`，命名空间为 `Endfield.Combat.Damage`。动作实例保存 `AttackSnapshot`：同一次出招的多个命中窗口共用快照，连招进入下一个动作并成功提交时重新取快照

场景中的 `CharacterDamageReceiver.Awake` 按顺序 −20 执行，在角色资源与状态初始化后组合本目标的一份只读面板、资源容器和状态控制器，普通 C# 的 `DamageReceiver` 持有这些引用，后续 HitDetection 确认目标后使用同一入口

## 2. 首版公式和数据单位

下列防御常数、承伤规则及招式倍率是供评审的 Demo 取值

攻击力已经包含 CharacterBuild、主副能力和面板 ATK 百分比，暴击伤害字段已是总倍率，菲比和祀的初始值均为 1.50 · [Stats 公式](../M1%20Core%20Data%20Foundation/M1.1%20StatSystem%20详细技术设计.md#2-固定公式与计算顺序)

| 乘区 | 建议计算式 | 例子 |
| --- | --- | --- |
| 基础伤害 | `snapshot.ATK × motionRatio` | 祀的 ATK 为 `(100 + 80) × (1 + 16 × 0.005 + 20 × 0.002) = 201.6`，招式倍率 1.0 得 201.6 |
| 出伤加成 | `max(0, 1 + snapshot.OutgoingDamageBonus)` | 两个限时出伤词条 +10%、+15% 同区相加，乘数为 1.25 |
| 暴击 | `roll01 < snapshot.CritRate` 时乘 `snapshot.CritDamage`，其余乘 1 | 抽样范围为 `[0, 1)`，暴击率 0.20 时 0.19 暴击、0.20 普通，每段抽一次 |
| 防御 | `100 / (100 + target.DEF)` | 两种伤害都过防御区，0 防乘 1，100 防乘 0.5 |
| 抗性 | `max(0, 1 − resistancePoints / 100)` | 物理取 `PhysicalResistance`，术式取 `ArtsResistance`<br>20 点乘 0.8，−10 点乘 1.1，100 点及以上乘 0 · [抗性单位与范围](../../Assets/Scripts/Runtime/Stats/Definitions/StatCatalog.cs) |
| 目标状态 | 物理取 `status.PhysicalDamageTakenMultiplier`，术式取 1 | 脆弱一层物理乘 1.10，同一击新施加的状态从后续命中起生效 · [Status 状态规则](./M2.3%20Status%20详细技术设计.md) |

最终伤害取以上各项乘积，内部保持 `double` 精度，显示层决定舍入

M6 首条连招支持 Physical、Arts，两者与可选的热或冰附着分别配置，后续元素招式登记专属抗性或增伤时，再按 Stats 已有的候选项扩展

输入倍率和失衡量须非负且有限，抽样值须在半开区间内，非有限计算结果在提交 HP 前报告错误

## 3. 公开入口与提交顺序

| 拟定入口 | 用途 |
| --- | --- |
| `CaptureAttack(IReadOnlyStatSet source, double outgoingDamageBonus) → AttackSnapshot` | 在出招约定时点调用，手动用例可从施加方 Effects 读出加成后传入<br>后续计算只读快照中的攻击数值 |
| `receiver.Calculate(attack, spec, roll01) → DamageBreakdown` | 输入本次攻击快照、该段的 `DamageSpec` 和暴击抽样，只读试算并返回各乘区与最终伤害 |
| `receiver.Apply(hit, attack, spec, roll01) → DamageResult` | 用已确认的 HitContext 标记来源、目标、接触点和战斗时间，按同一公式提交实际扣血、失衡和可选附着，返回明细与溢出。HitDetection 按攻击、窗口、目标去重，每个已确认命中调用一次 |
| `receiver.SubscribeApplied(listener) → IDisposable` | 订阅该目标发生的 HP 扣减事实，提供来源、目标和结果，载荷包含 HitContext、DamageApplied 和 DamageResult |

1. 在产生副作用前核对招式配置和数值，复制本次目标读数，计算一份 `DamageBreakdown`<br>预览与实际提交之间目标若换装或获得状态，实际提交重新读取命中当刻的数据
2. 将最终伤害一次传给 `ApplyDamage`，使用返回的 `HPLost` 与 `Overkill` 构造结果，HP 通知与 HUD 刷新由 Resources 同步完成
3. 本版建议在实际扣血且目标仍存活时，按“失衡积累 → 可选元素附着”的顺序提交本段的附带效果<br>致命一击保留扣血事实，归零后的角色行为由 Actors 接入<br>需要零伤害也能施加状态的独立招式可直接调用 Status
4. `HPLost > 0` 时，所有本段附带状态处理完毕后，用现有 `ChangeNotifier<T>` 发布一次扣血事实<br>0 HP 目标再次受击时，仍返回本次结算值及溢出，事实条数保持原值<br>表现侧按需租用反馈对象 · [M1.4 扣血事实契约](../M1%20Core%20Data%20Foundation/M1.4%20CombatContracts%20与%20Timing%20详细技术设计.md#22-从命中到扣血什么时候可以发布事实)

## 5. M6 连招验收

M6 在 `Assets/Scripts/Test/Editor/Damage/` 放置公式用例，场景联调集中在 `Assets/Scripts/Test/Editor/Combat/CombatExecutionSceneTests.cs`。EditMode 用例直接构造 `DamageSpec` 复算公式，进入 Play Mode 的场景用例从 Combos 提交 Action，经真实命中窗口取得本段参数并结算

| 用例 | 操作与预期 |
| --- | --- |
| 公式和暴击边界 | 从两份角色资产建立面板，参数化复算第 4 节前三行，同时断言 `Calculate` 保持目标满血且无事实<br>将目标物抗调为 −10、100 分别得到普通物伤 110.88、0，零伤行实际扣血为 0 |
| 提交顺序与零生命 | 用携带 35 失衡和一次热附着的非致命物理命中攻击 80/100 失衡的目标，扣血事实回调应能同时读到新的 HP、满槽失衡与热附着<br>再对 0 HP 目标提交正伤害，只返回溢出，事实数不增加 |
| 同一动作的两个命中窗口 | 祀的一个 Action 内配置物理两段，倍率分别为 0.6 和 1.4，均无附着和失衡。对默认满血菲比命中，双方无额外效果，每次抽样取 0.80。首段结算 60.48，剩余 HP 89.52，次段结算 141.12，实际扣血 89.52，溢出 51.60。同一窗口重复扫到菲比仍只结算一次。重置目标并在第二个窗口前取消动作，只观察到首段扣血 |
| 连招换段与场景反馈 | 按下表执行两个独立的攻击动作。两次成功出招各自产生快照，第一招保留出招时的增伤，第二招使用增伤到期后的快照 |

### CombatDemo 连招联合算例

| 步骤 | 操作 | 可观察结果 |
| --- | --- | --- |
| 准备 | 加载 CombatDemo，目标取 `Characters/TrainingTarget` 的敌对默认菲比，由 `Characters/SiRoot` 的祀使用临时两段连招，夹具绑定目标 HUD。两个连招动作的攻击段各填物理、倍率 1、无附着和失衡。夹具指定每次暴击抽样为 0.80，火花池容量和预热数均设 1 | 菲比 HP 为 150，DEF 为 100，物抗为 0，祀的 ATK 为 201.6 |
