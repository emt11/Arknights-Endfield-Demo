# M2.4 Damage 伤害结算详细技术设计 V1.0

**设计待评审**　祀出招时有增伤，命中前增伤消失，菲比在命中前才获得脆弱

这一击应保留祀出招时的攻击数据，并采用菲比受击时的防御与状态 · [M2 联合算例](./M2%20Runtime%20Foundation%20开发设计.md#3-一次贯穿四个模块的验收)

## 1. 三个取值时点

| 时点 | 谁持有数据 | 具体字段 |
| --- | --- | --- |
| 攻击提交 | Damage 创建只读 `AttackSnapshot`，调用方随该次攻击保存 | 从 `IReadOnlyStatSet` 复制 `ATK`、`CritRate`、`CritDamage` 和调用方提供的出伤加成合计值<br>用于标记施加方的引用与用于计算的数值分开，同一攻击的多段命中可复用数值副本 · [Stats 只读接口](../Assets/Scripts/Runtime/Stats/Runtime/StatReadModels.cs) |
| 每段确认命中 | 该段 `DamageProfile` 与目标的 `DamageReceiver` | 配置伤害类型、招式倍率、失衡积累和可选附着，现场读取目标 DEF、对应抗性点数、物理承伤倍率，为这一段取一份暴击抽样值 |
| 结算提交 | Resources 持有当前生命，Status 持有状态，Damage 返回 `DamageResult` | 计算明细保留各乘数，实际扣血与溢出直接取 `HealthLossResult`<br>已有血条自然收到资源通知 · [实际扣血入口](../Assets/Scripts/Runtime/Resources/Character/CharacterResourceContainer.cs) · [现有血条](../Assets/Scripts/Runtime/UI/HealthHud.cs) |

运行时放在 `Assets/Scripts/Runtime/Combat/Damage/`，命名空间为 `Endfield.Combat.Damage`

场景中的 `CharacterDamageReceiver.Awake` 按顺序 −20 执行，在角色资源与状态初始化后组合本目标的一份只读面板、资源容器和状态控制器，普通 C# 的 `DamageReceiver` 持有这些引用，后续 HitDetection 确认目标后使用同一入口

## 2. 首版公式和数据单位

下列防御常数、承伤规则及招式倍率是供评审的 Demo 取值

攻击力已经包含 CharacterBuild、主副能力和面板 ATK 百分比，暴击伤害字段已是总倍率，菲比和祀的初始值均为 1.50 · [Stats 公式](./M1.1%20StatSystem%20详细技术设计.md#2-固定公式与计算顺序)

| 乘区 | 建议计算式 | 例子 |
| --- | --- | --- |
| 基础伤害 | `snapshot.ATK × motionRatio` | 祀的 ATK 为 `(100 + 80) × (1 + 16 × 0.005 + 20 × 0.002) = 201.6`，招式倍率 1.0 得 201.6 |
| 出伤加成 | `max(0, 1 + snapshot.OutgoingDamageBonus)` | 两个限时出伤词条 +10%、+15% 同区相加，乘数为 1.25 |
| 暴击 | `roll01 < snapshot.CritRate` 时乘 `snapshot.CritDamage`，其余乘 1 | 抽样范围为 `[0, 1)`，暴击率 0.20 时 0.19 暴击、0.20 普通，每段抽一次 |
| 防御 | `100 / (100 + target.DEF)` | 两种伤害都过防御区，0 防乘 1，100 防乘 0.5 |
| 抗性 | `max(0, 1 − resistancePoints / 100)` | 物理取 `PhysicalResistance`，术式取 `ArtsResistance`<br>20 点乘 0.8，−10 点乘 1.1，100 点及以上乘 0 · [抗性单位与范围](../Assets/Scripts/Runtime/Stats/Definitions/StatCatalog.cs) |
| 目标状态 | 物理取 `status.PhysicalDamageTakenMultiplier`，术式取 1 | 脆弱一层物理乘 1.10，同一击新施加的状态从后续命中起生效 · [Status 状态规则](./M2.3%20Status%20详细技术设计.md) |

最终伤害取以上各项乘积，内部保持 `double` 精度，显示层决定舍入

M2 首版支持 Physical、Arts，两者与可选的热或冰附着分别配置，后续元素招式登记专属抗性或增伤时，再按 Stats 已有的候选项扩展

输入倍率和失衡量须非负且有限，抽样值须在半开区间内，非有限计算结果在提交 HP 前报告错误

## 3. 公开入口与提交顺序

| 拟定入口 | 用途 |
| --- | --- |
| `CaptureAttack(IReadOnlyStatSet source, double outgoingDamageBonus) → AttackSnapshot` | 在出招约定时点调用，手动用例可从施加方 Effects 读出加成后传入<br>后续计算只读快照中的攻击数值 |
| `receiver.Calculate(attack, profile, roll01) → DamageBreakdown` | 只读试算，返回原始伤害、出伤倍率、暴击标记及倍率、防御倍率、抗性倍率、状态倍率与最终伤害 |
| `receiver.Apply(attack, profile, roll01) → DamageResult` | 用同一公式与传入抽样完成一次实际提交，返回本次明细、实际扣血和溢出<br>每个已确认命中调用一次，窗口与重复碰撞去重归 HitDetection |
| `receiver.SubscribeApplied(listener) → IDisposable` | 订阅该目标发生的 HP 扣减事实，提供来源、目标和结果，接入共享 `DamageApplied` 契约时由发布处映射已有字段 |

1. 在产生副作用前核对招式配置和数值，复制本次目标读数，计算一份 `DamageBreakdown`<br>预览与实际提交之间目标若换装或获得状态，实际提交重新读取命中当刻的数据
2. 将最终伤害一次传给 `ApplyDamage`，使用返回的 `HPLost` 与 `Overkill` 构造结果，HP 通知与 HUD 刷新由 Resources 同步完成
3. 本版建议在实际扣血且目标仍存活时，按“失衡积累 → 可选元素附着”的顺序提交本段的附带效果<br>致命一击保留扣血事实，归零后的角色行为由 Actors 接入<br>需要零伤害也能施加状态的独立招式可直接调用 Status
4. `HPLost > 0` 时，所有本段附带状态处理完毕后，用现有 `ChangeNotifier<T>` 发布一次扣血事实<br>0 HP 目标再次受击时，仍返回本次结算值及溢出，事实条数保持原值<br>表现侧按需租用反馈对象 · [M1.4 扣血事实候选设计](./M1.4%20CombatContracts%20与%20Timing%20详细技术设计.md#22-从命中到扣血什么时候可以发布事实)
