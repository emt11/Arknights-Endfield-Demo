# M1.1 StatSystem 详细技术设计 V1.1

**设计版本**　V1.1　·　**实现状态**　已实现，待用户验收　·　**EditMode 验证**　15 / 15 通过

每名战斗角色持有独立的 `StatSet`。给定同一份属性定义、角色初值和有效 Modifier 集合，Stats 应得到唯一的最终值，并能指出每条修正来自哪个实例。调用方在一次变更提交后即可读取同一版本的 ATK、MaxHP 和其他属性

## 1. 模块位置与工程基线

| 依据 | 对本模块的约束 |
| --- | --- |
| Architecture V2.0 | Stats 位于 `Assets/Scripts/Runtime/Stats/`，程序集和命名空间均为 `Endfield.Stats`。公开能力包括读取、修改、按来源移除、快照、计算明细和变更通知 |
| M0 工程审计 | 当次审计确认 Unity `6000.3.28f1`、Test Framework `1.6.0`、两套可复用角色美术资源；当时 `Assets/ScriptObjects/` 无业务数据。模型、Avatar 和场景出生引用均不是创建 StatSet 的前置条件 |
| 《设计属性系统.txt》 | 采用稳定属性 ID、角色独立实例、四种 Modifier、主副属性参与 ATK、依赖图和缓存。下列系数、上下限、覆盖优先级与提交时机均为 **Demo 设计提案** |
| M1.1 验证范围 | 用两份内存初值验证角色隔离，用人工可复算的数据验证规则。Phoebe 与 Si 的真实初值、主副属性和成长系数仍待配置，本设计不为两人指定数值 |

本模块拥有属性最终值、修正条目和计算缓存。当前 HP/SP、效果持续时间、装备成长、单次攻击结算分别由各自模块管理。整体职责与依赖见 [Architecture V2.0 第 2、3、9 章](./仿终末地战斗系统设计方案.md)

## 2. 属性分类、单位与首批范围

每个定义有两个独立维度。**业务分类**决定属性的含义和单位，**取值方式**决定初始计算值来自外部输入还是派生公式。这样 `MaxHP` 可以同时属于“资源上限”和“派生值”

| 业务分类 | 属性示例 | 单位、取值和范围 |
| --- | --- | --- |
| 四维基础属性 | `STR`、`AGI`、`INT`、`WIL` | `Point`，输入型，下限 0。CharacterBuild 从四维中选择主、副属性 |
| 基础战斗值 | `BaseATK`、`WeaponATK`、`FixedATK`、`BaseDEF`、`BaseHP` | `Point`，输入型。基础攻击与武器攻击先接受百分比加成，随后加入固定攻击 |
| 攻击加成 | `ATKPercentBonus`、`AttributeATKBonus` | `Ratio`，0.30 表示增加 30%。前者汇总攻击百分比词条，后者由最终主、副属性派生 |
| 战斗面板与资源上限 | `ATK`、`DEF`、`MaxHP`；按需增加 `MaxSP` | `Point`，ATK、DEF、MaxHP 下限为 0。Resources 读取上限并管理当前值 |
| 暴击 | `CritRate`、`CritDamage` | CritRate 为 `Ratio`，0.10 表示 10% 概率，范围 [0, 1]。CritDamage 为 `Multiplier`，1.50 表示总倍率 1.5 |
| 抗性、伤害与治疗加成 | `PhysicalResistance`、`ArtsResistance`、`PhysicalDMGBonus`、`ArtsDMGBonus`、`HealingBonus`、`HealingReceived` | 抗性用 `ResistancePoint`，20 表示 20 个抗性点，Damage 负责换算减伤。伤害与治疗加成用 `Ratio`，0 表示无加成 |
| 特殊属性 | `AttackSpeed`、`MoveSpeed`、`StaggerDamageBonus`、`UltimateGain` | 攻速为 `Multiplier`，1 为原速；移速为 `MetersPerSecond`；后两项为 `Ratio`，0 为无加成 |

**首批验收数据**覆盖四维、ATK 所有输入及派生项、BaseHP、MaxHP、BaseDEF、DEF、CritRate。其他条目确定分类和扩展位置，接入时按实际需要补定义与公式。新增输入型属性只需登记定义；新增派生关系还需声明公式和依赖。核心查找使用稳定 `StatID`，显示名或枚举序号变化不影响引用

完整角色定义集要求调用方显式提供四维、BaseATK、BaseDEF 和 BaseHP；WeaponATK、FixedATK、ATKPercentBonus 和 CritRate 的输入默认值为 0。派生项由公式产生初值。首批基础点数、DEF、MaxHP、CritRate 支持第 4 节的四种操作；攻击加成池与最终 ATK 的限制见该节末尾

## 3. 数据模型与所有权

| 模型 | 核心数据 | 生命周期与约束 |
| --- | --- | --- |
| `StatDefinition` | StatID、显示名、分类、`UnitType`、取值方式、初值策略、可选上下限、取整策略、允许的 Modifier 操作、可选公式 | 定义在运行期只读，可由 ScriptableObject 承载。输入型明确必填项或默认值；每个派生项绑定一个公式 |
| `StatSet` | 定义索引、从外部传入的不可变公式绑定、实例集合、来源索引、Revision | 每个角色一份。创建时校验绑定并建立依赖图，初始 Revision 为 0。适用同一套角色定义的实例可共享只读定义 |
| `StatInstance` | 对应 StatID、输入型基础值、该属性的 Modifier 集合、已提交最终值、Dirty 标记 | StatSet 内部持有。派生型的起始值来自公式；调用方只能通过 StatSet 读写 |
| `StatModifier` | SourceID、EntryID、目标 StatID、Operation、Value、Priority | 一条记录只作用于一个目标。记录的身份由来源和条目键确定，数值或优先级调整沿用该身份 |
| `FormulaDefinition` | 公式标识、输出 StatID、求值器类型、具名输入槽、系数 | 声明一个派生节点需要的数据；主、副属性槽在创建时绑定到本角色的具体 StatID |
| `FormulaEvaluator` | 读取已解析的输入值与系数，输出一个有限数值 | 纯计算，与角色对象及缓存无关。第 6 节规定首版的两种求值器 |
| `StatDependencyGraph` | 输入与输出之间的边、反向索引和拓扑序 | 按已解析的公式输入建图，在 StatSet 生命周期内固定 |
| `StatSnapshot` 与 `StatChangeSet` | 快照含 StatSet 标识、Revision 和所选最终值；变更集含 Revision、变更的 StatID 及其旧值、新值 | 都保存已提交值。快照独立持有不可变数据，可交付给后台读取 |
| `StatBreakdown` | StatSet 标识、Revision、StatID、UnitType、公式输入、来源条目、各阶段结果与最终值 | 为一次诊断查询生成只读明细，见第 8 节 |

**创建约束**　StatID 大小写敏感、非空且唯一。必填初值缺失、未知的初值键、派生项收到初值、主副属性相同或不属四维、上下限倒置、循环依赖均使创建失败。默认值只用于定义明确允许省略的输入。启用 ATK 公式的角色必须提供有效主副属性；纯数值测试可使用只含所测项目的小型定义集

## 4. Modifier 计算顺序

对每个属性先求起始值 B，输入型取基础值，派生型取本轮公式结果。随后按下表计算，Priority 仅用于 Override

**单位校验**　Flat 与 Override 的操作数使用目标属性的 UnitType，AdditivePercent 使用 Ratio，Multiplicative 使用 Multiplier。配置校验按这条规则解释词条数值，核对显式标注的操作数单位，并检查目标定义允许的操作。例如 CritRate 为 0.20 时，Flat +0.10 使它变为 0.30，Multiplicative ×1.10 使它变为 0.22；两个例子分别从同一基础值计算

| 顺序 | 操作 | 运算规则 |
| --- | --- | --- |
| 1 | Flat | 将所有固定增减量求和，得到 `B + ΣFlat`，Value 使用目标属性自身单位 |
| 2 | AdditivePercent | 将所有百分比相加，再乘 `1 + ΣPercent`；+20% 写为 0.20，−10% 写为 −0.10 |
| 3 | Multiplicative | 逐项相乘，Value 是直接倍率，×1.20 写为 1.20。允许 0，负倍率拒绝 |
| 4 | Override | 取最高 Priority 的覆盖值，移除后回退到下一优先级。提交时，同一 StatID 的每个 Priority 至多留一条 Override，包含被更高优先级遮盖的条目；冲突时整批失败 |
| 5 | 取整与限幅 | 按该属性的策略保留小数或向下取整，最后执行上下限裁剪。上限、下限同样约束 Override 结果 |

未提供的加法项视为 0，乘法项视为 1。百分比和可低于 −100%，先执行代数计算，再应用目标属性的边界。每层按稳定条目键累计，避免登记顺序改变浮点求和顺序。输入、运算中间值和最终结果须为有限数值；计算使用双精度，M1.1 默认保留小数。显示位数由展示方决定

**通用计算例**　某点数属性 B = 100，同时有 Flat +20、AdditivePercent +25% 和 −5%、Multiplicative ×1.5 和 ×0.5，结果为 `(100 + 20) × (1 + 0.25 − 0.05) × 1.5 × 0.5 = 108`。若再加 Override 150，且该定义上限为 120，最终读数为 120

**ATK 词条的落点**　“基础武器攻击 +200”记为对 `WeaponATK` 的 Flat 200；“攻击力 +30%”记为对 `ATKPercentBonus` 的 Flat 0.30；“固定攻击 +50”记为对 `FixedATK` 的 Flat 50。首批定义中 `ATKPercentBonus` 只接收 Flat，`AttributeATKBonus` 只读，最终 `ATK` 仅允许显式 Override。入口按定义拒绝其他操作，从而避免同一词条先进入 ATK 公式又在公式外重复放大

## 5. 来源标识与移除

- **SourceID** 标识一次具体来源实例。调用方为每个实际来源分配一个稳定值，逻辑组成是来源域和实例号，例如 `Equipment/17`、`Effect/42`。同一 StatSet 内，不同实例持不同 ID，已退役的 ID 在该 StatSet 生命周期内不再分配。两个角色各自独立管理作用于自己的记录
- **EntryID** 是来源内部稳定的条目键。同一来源的“武器攻击”和“攻击百分比”使用不同键。完整键为 `(SourceID, EntryID)`，在一个 StatSet 内唯一。按来源域的序数文本顺序、实例号数值、EntryID 数值依次升序，用于浮点累计与诊断展示；Override 的胜出条件由第 4 节定义
- **增加与替换**　重复增加同一键视为调用冲突，整批拒绝。刷新同一装备或效果使用 `ReplaceSource`，一个调用以新条目集合替换旧集合，省略的旧条目一并删除。重复提交内容完全相同的替换为无操作
- **撤销与重试**　`RemoveModifier` 精确移除一条，`RemoveSource` 移除该来源在所有属性上的条目。重复移除返回 0；按剩余输入重新求值。其他来源同时生效、倍率为 0 或 Override 存在时，撤销规则相同
- **归属**　同一 StatSet 维护来源到条目的反向索引。销毁 StatSet 时释放索引、缓存和订阅；延迟到达的移除命令须仍指向原 StatSet 的生命周期

## 6. 派生属性与依赖图

**角色绑定**　CharacterBuild 决定主、副属性，创建 StatSet 时传入不可变的公式绑定。以主 INT、副 WIL 为例，Stats 将两个输入槽解析成 INT、WIL，分别建立到 AttributeATKBonus 的边。调整 INT 的数值沿已有边传播；若角色的主属性身份改为 STR，调用方以新绑定创建 StatSet

**公式执行**　创建时用 FormulaDefinition 的求值器类型选取固定求值器，校验输出与所属定义一致、输入槽齐全、系数数量和单位匹配。未知求值器或无法解析的槽使创建失败，并报告公式与属性标识。求值器只读取声明的输入；依赖排序、Modifier、缓存和事件均使用同一条属性计算流程

| 首版求值器 | 输入与计算 | 用于 |
| --- | --- | --- |
| 加权和（WeightedSum） | 每个输入乘以配置系数后相加，系数表达输入到输出的单位换算 | DEF 用权重 1 读取 BaseDEF；MaxHP 对 BaseHP、STR 使用权重 1、5；AttributeATKBonus 对主、副属性使用 0.005、0.002 |
| ATK 专用求值器 | 五个具名输入分别参与基础攻击、普通百分比、固定攻击和主副属性乘区 | 执行下表 ATK 公式，保留各乘区次序 |

表内系数为可替换的 Demo 测试参数

| 派生节点 | 直接读取的最终值 | 首批公式或扩展约定 |
| --- | --- | --- |
| `AttributeATKBonus` | 主属性、副属性 | `主属性 × 0.005 + 副属性 × 0.002` |
| `ATK` | BaseATK、WeaponATK、ATKPercentBonus、FixedATK、AttributeATKBonus | `[(BaseATK + WeaponATK) × (1 + ATKPercentBonus) + FixedATK] × (1 + AttributeATKBonus)` |
| `MaxHP` | BaseHP、STR | `BaseHP + STR × 5` |
| `DEF` | BaseDEF | 首批采用恒等公式，得到起始 DEF 后按本属性的 Modifier 和范围计算 |
| 抗性与受治疗加成 | 对应基础值及 AGI、INT、WIL | 扩展时分别声明 AGI → PhysicalResistance、INT → ArtsResistance、WIL → HealingReceived；具体换算系数待对应设计评审 |

建图时校验缺失依赖、自引用和环；错误报告列出缺失键或完整环路，例如 `A → B → C → A`。公式只能读取已声明的输入，无法读取当前 HP、敌方状态、时钟或另一个角色。相互独立的节点按 StatID 序数排序，让求值和事件顺序可复现

**ATK 对照算例**　BaseATK = 100、WeaponATK = 200、FixedATK = 50、INT = 100、WIL = 50，主 INT、副 WIL，因此主副属性加成为 0.60

| 有效来源 | ATKPercentBonus | 计算 | 预期 ATK |
| --- | ---: | --- | ---: |
| 装备 A | 0.30 | (300 × 1.30 + 50) × 1.60 | 704 |
| 装备 A 和临时来源 B | 0.50 | (300 × 1.50 + 50) × 1.60 | 800 |
| 移除 B，保留 A | 0.30 | (300 × 1.30 + 50) × 1.60 | 704 |

参考文本第五节的 704 可复算。末尾示例给出的 792 与所列公式不一致；若按末尾的算式省略 FixedATK，临时来源生效与移除后的结果分别为 720 和 624。M1.1 验收统一使用上表含 FixedATK 的一组输入

**独立乘区的扩展位置**　当具体玩法需要独立 ATK 倍率时，为其定义 Multiplier 单位的输入，声明依赖，并在 ATK 求值器的公式和验收算例中同时标明乘入位置。现阶段使用上表的五个输入，普通攻击百分比统一进入 ATKPercentBonus

## 7. 缓存、Dirty 传播与通知

**求值时机**　变更在写入批次内延迟计算，提交时求完受影响节点。提交成功后，读值直接命中缓存。这一选择允许 Resources 的上限订阅者与同一帧读取快照的调用方同时看到一致的数值，也能在发布前拒绝无效计算

1. **准备**　在候选数据上按命令顺序校验并应用写入。全部命令处理完毕，再按 `(StatID, Priority)` 检查 Override 的唯一性。冲突诊断列出属性、优先级及冲突条目的完整来源键。旧装备 A 与新装备 B 同优先级时，同批先加 B 再移除 A 可以成功；若最终同时保留 A、B，则整个批次回滚。通过校验后，仅有净变化的节点进入 Dirty 队列
2. **传播**　沿反向依赖表从直接改动项找到全部下游。每个受影响节点标记一次；菱形依赖的汇合点也只标记一次。未触达的分支继续使用既有缓存
3. **求值**　按创建时的拓扑序处理 Dirty 集合，用上游本批次的新值与其他节点的缓存求值。每个受影响节点每批最多计算一次；同一节点收到多个 Modifier 也只重算一次
4. **提交**　全部成功后一次发布基础值、条目、来源索引与缓存，清除 Dirty，Revision 加一。任一步校验失败或计算出现非有限值，保留旧数据、旧版本和旧快照，返回出错的来源键或属性键
5. **通知**　比较本批前、后经过限幅的最终值，按拓扑顺序生成一个 StatChangeSet，同一属性最多一项。采用已提交数值的精确相等判定，正负零等价；测试断言另设浮点容差。来源变了但最终值相同，Revision 仍推进，数值事件为空时不派发
6. **回调**　发布后逐个同步调用订阅者。单个订阅者抛出异常时，记录异常、StatSet 标识与已提交的 Revision，随后继续投递同一变更集。回调可以读取已提交值及快照；回调期间写入同一 StatSet 会立即返回错误，该命令随即结束。需要修改属性的订阅者在通知结束后的自身逻辑中显式提交新批次

例：同批将 STR 从 10 改为 12、BaseHP 从 100 改为 120，MaxHP 从 150 直接变为 180。仅产生一条 MaxHP 变更记录，旁支 DEF 的计算次数为 0

### 7.1 线程与快照的生命周期

| 访问方式 | 线程约定 |
| --- | --- |
| 创建或销毁 StatSet，执行写操作、求值、提交、订阅、解除订阅和通知 | 统一在 Unity 主线程按顺序执行 |
| 读取实时值或 Revision，查询 Modifier、生成明细、创建 Snapshot | 均访问当前 StatSet，只能在主线程调用。Editor 和开发构建在公开入口检测非法线程访问并给出诊断 |
| 读取已经创建并交付的 Snapshot | 可在工作线程只读。通过任务参数等线程安全方式交付；快照独立保存标识、版本和值，内部不持有 Unity 对象、StatSet 或可变集合的引用。原 StatSet 更新或销毁后仍可读 |

运行时使用已校验的只读定义。由 Unity 资产提供的配置在主线程读取；后台工作只消费已交付的快照

## 8. 公开 API 与跨模块接口

每个角色通过 `StatSet.Create` 传入定义、初值和主副属性绑定。使用可序列化的属性目录时，可调用 `StatCatalog.CreateSet`。数值写入由持有 `StatSet` 的调用方发起，读取端使用 `IReadOnlyStatSet`

| 操作 | 输入 → 输出 | 行为契约 |
| --- | --- | --- |
| `Create` | 定义集合、初值、必要的不可变公式绑定 → StatSet 或诊断 | 校验绑定和求值器，完成初始化求值后发布初始版本 |
| `GetValue` / `TryGetValue` | StatID → 最终值 / 是否存在及最终值 | GetValue 遇未登记 ID 报错；可选属性通过 TryGetValue 探测。读取次数不影响 Revision 或计算次数 |
| `SetBase` | 输入型 StatID、有限基础值 → 提交结果 | 只修改基础输入；外部直接写 ATK、MaxHP 等派生节点会被拒绝 |
| `AddModifier` / `RemoveModifier` | 单条记录 / 完整条目键 → 提交结果 | 增加成功返回已登记键；移除返回实际移除数 0 或 1 |
| `ReplaceSource` / `RemoveSource` | SourceID 和该来源的全量条目 / SourceID → 提交结果 | 替换覆盖该来源整组，空集合等同移除；RemoveSource 返回实际移除条数 |
| `ApplyBatch` | 写操作的有序集合 → 成功与否、Revision、各操作结果或首个错误 | 单次写入是单命令批次。按批次最终集合校验 Override 冲突，失败时值、Revision、来源索引及通知次数均保持提交前状态 |
| `Snapshot` | 一组 StatID → 只读 StatSnapshot | 主线程捕获同一已提交版本，重复 ID 合并，任一未知 ID 则整组失败。快照创建只复制缓存值，可独立跨线程读取 |
| `GetModifiers` | StatID → 该属性已登记条目的只读副本 | 返回来源键、目标、操作、数值及优先级，含暂未胜出的覆盖项。未知属性与 GetValue 同样处理 |
| `GetBreakdown` | StatID → StatBreakdown | 主线程按需解释当前已提交值，未知属性与 GetValue 同样处理。以同一 Revision 的基础值、已绑定的公式输入和来源条目生成明细 |
| `Subscribe` | 变更集接收方 → 可解除的订阅 | 只接收订阅之后的数值变化；初始值通过 Snapshot 读取。解除后停止通知 |

**如何解释一笔 ATK**　GetBreakdown 在查询时复用实际求值器和 Modifier 计算顺序，记录基础输入或派生公式各输入的 StatID、单位与值、相关输入上的来源键、目标自身的 Modifier、各阶段小计、胜出的 Override 键、取整与限幅结果。第 6 节的 704 可展开为基础攻击 300 → 普通百分比后 390 → 加固定攻击后 440 → 主副属性加成后 704，并能定位 0.30 来自装备 A。明细是该版本的只读副本；生成过程只读已提交状态，不更新缓存、Revision 或事件。普通读值和每批提交均无需生成明细

| 相邻模块 | 需要的最小交互 | 数据所有权 |
| --- | --- | --- |
| CharacterBuild | 选择主、副属性，将绑定与初值传给 Create，按需提交基础值或来源修正 | 选择权、成长与装备归 CharacterBuild；Stats 持有绑定副本并计算最终值 |
| Effects | AddModifier、ReplaceSource、RemoveSource | 效果实例负责其 SourceID 的使用时机；Stats 只保存该来源当前有效的数值条目 |
| Resources | 读取 MaxHP 等上限，订阅已提交的上限变化 | MaxHP 从 1000 变为 1200 时，Stats 发布这两个值；当前 HP 若为 800，如何调整由 Resources 决定 |
| Damage | 按需读取同一 StatSet 的指定属性快照 | Stats 提供带版本的面板数值；攻击者与目标快照的选取时机、伤害结果和结算归 Damage |
