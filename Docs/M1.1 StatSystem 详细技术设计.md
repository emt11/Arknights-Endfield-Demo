# M1.1 StatSystem 详细技术设计 V1.5

**V1.5 暴击伤害 · 面板定义与验收见第 1.2、5.4 节**

每名角色持有一份独立的 `StatSet`。装备和 Buff 按来源更新属性，Stats 按固定公式计算最终值，角色属性 UI 按组显示属性名和当前最终值。四维固有收益与主副能力加成见第 2 节。V1.5 将暴击总伤害倍率纳入角色面板，供后续 Damage 结算读取。模块边界见 [Architecture V2.0](./仿终末地战斗系统设计方案.md)

## 1. 属性、分组与元素边界

### 1.1 六个面板分组

每个已登记的 `StatId` 恰好属于一个 `StatGroup`。V1.5 将 `CritDamage` 追加在 `HealingReceivedBonus` 之后，面板共 19 项。现有角色资产中的属性 ID 继续有效

| StatGroup | 已登记属性及显示名 | 后续接入点 |
| --- | --- | --- |
| `PrimaryAttributes` · 基础属性 | `STR` 力量、`AGI` 敏捷、`INT` 智识、`WIL` 意志 | 主、副属性从这四项中各选一项，两者须不同 |
| `BaseCombat` · 基础战斗 | `BaseATK` 基础攻击、`WeaponATK` 武器攻击、`FixedATK` 固定攻击、`BaseDEF` 基础防御、`BaseHP` 基础生命、`ATKPercentBonus` 面板攻击力百分比加成 | `FixedDEF` 固定防御，启用时明确落入 DEF 公式的位置 |
| `DerivedCombat` · 战斗面板 | `ATK` 最终攻击、`DEF` 最终防御、`MaxHP` 最大生命、`CritRate` 暴击率、`AttributeATKBonus` 主副属性攻击加成、`CritDamage` 暴击伤害 | 单次命中的暴击判定与倍率应用归 Damage |
| `DamageBonus` · 伤害加成 | 暂无 | 物理、术式及四种元素增伤，见 1.3 |
| `Resistance` · 抗性 | `PhysicalResistance` 物理抗性、`ArtsResistance` 法术抗性 | 四种单元素抗性仍为候选 |
| `Special` · 特殊属性 | `HealingReceivedBonus` 受治疗效率 | `AttackSpeed` 攻击速度、`MoveSpeed` 移动速度、`StaggerDamageBonus` 失衡伤害加成、`UltimateGain` 终结技能量获取、`HealingBonus` 施加治疗加成 |

**分组与取值方式独立。** 例如暴击率和最终攻击都展示在 `DerivedCombat` 下，`CritRate` 是可写基础值的直接属性，`ATK` 则由固定公式计算。`ATKPercentBonus` 放在基础战斗组，因为它参与面板 ATK 公式；`ElectricDMGBonus` 属于伤害加成组，供单次伤害结算读取。两者可以独立调节

### 1.2 一份定义供配置、展示与查询使用

一条 `StatDefinition` 描述一个属性，包含 `StatId`、`Group`、`DisplayName`、`Unit`、`DefaultValue`、`Minimum` 和 `Maximum`。其中 `Required` 标记必填初值，`Derived` 标记由公式提供起始值的属性

`StatCatalog` 持有全项目共用的一张固定定义表。静态方法 `Get(StatId)` 查单项定义，`GetByGroup(StatGroup)` 按组返回只读定义序列，两者均可在没有目录资产实例时使用。Inspector 按第 1.1 节的组序展示，组内按 StatId 顺序排列，新增 ID 追加到枚举。每份目录资产只保存本项目可调的三项公式系数，见第 1.4 节

| 属性 | 初值与单位 | 生效规则 |
| --- | --- | --- |
| 四维、`BaseATK`、`BaseDEF`、`BaseHP` | 角色配置必填，点数 | 下限 0，缺少必填初值时创建失败 |
| `WeaponATK`、`FixedATK` | 默认 0 点 | 两者进入 ATK 公式的位置不同 |
| `ATKPercentBonus`、`CritRate` | 默认 0，比例 | 攻击力加成参与 ATK 公式，暴击率最终范围为 [0, 1] |
| `CritDamage` | 可选直接属性，默认 1.50，比例 | 暴击总伤害倍率。最终值下限为 0，可超过 1。1.50 显示为 150%，显式配置为 0 时保留 0 |
| `AttributeATKBonus` | 公式输出，比例 | 由主、副属性推导起始值，经自身词条修正后供 ATK 读取 |
| `ATK`、`DEF`、`MaxHP` | 公式输出，点数 | 下限 0。三项均按第 3 节修正各自的公式结果 |
| `PhysicalResistance`、`ArtsResistance` | 公式输出，点数 | 分别从 AGI、INT 计算，目标自身的 Flat 以点计，可将最终抗性降为负值 |
| `HealingReceivedBonus` | 公式输出，比例 | 从 WIL 计算。0.10 在 UI 上显示为 10%，目标自身的 Flat +0.02 表示增加 2 个百分点 |

物理抗性、法术抗性和受治疗效率均为 `Derived = true`、`Required = false`，元数据默认值为 0。创建面板时以公式提供起始值，零能力、无词条时结果为 0。三项沿用定义的开放上下界及有限数值校验，只能通过上游能力或本属性词条调整。角色初值 Inspector 只列直接属性，现有角色配置无需新增三个输入字段

角色初值 Inspector 和角色属性 UI 共用组序、显示名和单位。UI 中每个有已登记属性的 `StatGroup` 对应一个分组对象，组内每个 `StatId` 对应一行。组成员由 `StatCatalog` 统一定义，行内数值取自当前角色的 `StatSet`。每行只显示 `DisplayName` 和按 `Unit` 格式化的最终值，例如「暴击率　20%」

**暴击率与暴击伤害**　`CritRate` 表示单次命中的暴击概率。`CritDamage` 保存暴击时使用的总倍率，`Required = false`、`Derived = false`。角色初值省略该项时采用 Demo 默认值 1.50，在 Inspector 的「暴击伤害 (%)」输入 175 时，保存 1.75，UI 显示 175%。旧角色配置自动采用默认值

两项分别接受第 3 节的来源词条。以默认倍率为起点，装备提供 `CritDamage Flat +0.20` 后得到 1.70，单独提供 `AdditivePercent +0.20` 时得到 1.80。后续 Damage 在暴击判定成功时将该次伤害乘以 `GetValue(StatId.CritDamage)` 一次，例如基准伤害 100、倍率 1.50，暴击结果为 150。Stats 只提供这两项最终值

### 1.3 元素相关属性与启用条件

下表列出伤害类型对应的属性。V1.4 中，物理抗性和法术抗性随四维计算，所有角色进场时即有这两项数值。伤害加成与四种单元素抗性仍按招式需要启用。伤害加成记录在攻击者面板，抗性记录在受击者面板

| 属性类别 | 单次攻击 DamageType | DamageBonus 组的 StatId | Resistance 组的 StatId |
| --- | --- | --- | --- |
| 物理 | `Physical` | `PhysicalDMGBonus` | `PhysicalResistance`（本次派生） |
| 术式通用 | `Arts` | `ArtsDMGBonus` | `ArtsResistance`（本次派生） |
| 元素 · 热 | `Heat` | `HeatDMGBonus` | `HeatResistance` |
| 元素 · 电 | `Electric` | `ElectricDMGBonus` | `ElectricResistance` |
| 元素 · 自然 | `Nature` | `NatureDMGBonus` | `NatureResistance` |
| 元素 · 冰 | `Cryo` | `CryoDMGBonus` | `CryoResistance` |

`ArtsResistance` 是寒冷、灼热、电磁、自然伤害共用的法术抗性。四种单元素抗性各有独立的候选 ID。接入某一元素时，再登记该招式需要的候选属性

- **伤害加成**是直接属性，默认 0，单位为比例。Flat +0.20 表示该类型的伤害加成增加 20 个百分点
- **单元素抗性**在启用时作为直接属性，默认 0 点。例如基础电抗 20 点，施加 Flat −30 点后得到 −10 点，移除来源后恢复到 20 点。物理抗性和法术抗性的公式见第 2 节
- **Damage** 读取受击者适用的抗性点数，负责将其换算为实际伤害。通用与单元素抗性如何共同参与一次命中，由 Damage 定义
- **治疗结算**读取受治疗者的 `HealingReceivedBonus`。候选的 `HealingBonus` 属于施加治疗者，二者可以分别取值。Stats 提供面板数据，Resources 负责更新当前生命

| 概念 | 归属与用法 |
| --- | --- |
| `StatGroup` | Stats 的面板组织标签，用于展示和查询。计算器按属性取值方式求起始值，再按统一顺序处理词条 |
| `DamageType` | 由单次攻击配置选择，供 Damage 匹配本次要读取的面板数值。同一角色的普攻可为 Physical，战技可为 Electric。Stats 的定义和计算只依赖自身的 StatId |
| `StatusType` | 由招式单独配置是否施加、施加何种附着。预留热、电、自然、冰四种附着类型。Status 持有附着实例、层数、持续时间和消费规则；Effects 继续管理普通 Buff 的生命周期 |

例如一段电伤战技可以只造成电伤，另一段可以同时配置施加电附着。两者都可以读取同一份面板。元素增伤沿用 `StatSet` 和 `ReplaceSource`，附着和反应规则留在对应玩法模块

### 1.4 从 Inspector 的角色初值到运行时面板

Phoebe、Si 的角色 Prefab 分别引用自己的 `CharacterStatProfile`。配置中的「角色显示名」支持中文，供属性面板和装备按钮使用，留空时显示配置资产名。进场时，Prefab 上的 `CharacterStats` 从配置创建独立的 `StatSet`。三项公式系数来自共享的 `StatCatalog`，将来 CharacterBuild 可以通过同一创建入口传入角色初值。[角色 Prefab](../Assets/Prefabs/Characters) · [两套角色配置与共享目录](../Assets/ScriptObjects/Stats)

| 要做什么 | 在哪里操作 | 数据如何生效 |
| --- | --- | --- |
| 调整某个角色的初值 | 从该角色的 Prefab 打开初值配置，按 `StatGroup` 展开直接属性，填写标有单位的数值，选择主、副属性 | 四维及 `BaseATK`、`BaseDEF`、`BaseHP` 为必填。可选输入省略时采用定义中的默认值。派生属性由公式生成 |
| 调整公式系数 | 在 `StatCatalog` 编辑主属性攻击系数、副属性攻击系数和每点 STR 提供的生命值 | 三项已有系数继续可调。V1.4 的抗性曲线和意志转换率使用第 2 节的固定常量，角色配置继续共用同一份目录 |
| 查看本次战斗的最终值 | 在 Play Mode 中打开当前角色的属性 UI，按组查看各项最终值 | `CharacterStatProfile.CreateSet` 提供初值和主副属性，`StatCatalog.CreateSet` 将三项系数传给 `StatSet.Create`。每个角色拥有独立的基础值、来源词条与最终值缓存 |

例如 `BaseHP = 100`、`STR = 10` 时，角色属性 UI 在战斗面板组显示「最大生命　150」。Resources 通过 `GetValue(StatId.MaxHP)` 读取同一个 150。穿脱装备只更新该角色的运行时数值，再次进场时从初值资产重新创建面板

## 2. 固定公式与计算顺序

### 2.1 四维的固有收益与主副能力

四项能力各自提供一项固有收益，所有角色都走这四条计算路径。角色选定的主能力和副能力再额外参与攻击加成。计算时先给四维应用各自的 Modifier 和下限 0，再取其最终值的整数部分作为能力公式输入。例如，敏捷 100.9 在公式中按 100 计算，缓存中的敏捷仍为 100.9。这一取整约定也适用于既有的力量生命和主副能力攻击公式，是 V1.4 对小数能力值的行为变更。[机制依据《终末地数据机制导论》§4.2](https://github.com/NagiYume/AKEDatabase/blob/main/public/CH/research/终末地数据机制导论.md#42干员基础属性)

| 能力输入（取整后） | 固有收益的公式起始值 | 默认系数下的结果 |
| --- | --- | --- |
| STR 力量 | `MaxHP = BaseHP + STR × 5` | 100 力量贡献 500 点最大生命 |
| AGI 敏捷 | `PhysicalResistance = R(AGI)` | 100 敏捷贡献约 9.09 点物理抗性 |
| INT 智识 | `ArtsResistance = R(INT)` | 200 智识贡献约 16.67 点法术抗性 |
| WIL 意志 | `HealingReceivedBonus = WIL × 0.001` | 100 意志给受治疗者 0.10 的比例加成，显示为 10% |

两种通用抗性共用一个固定函数 `R(x) = 100 × (1 − 1 / (1 + 0.001 × x))`，单位为点。`R(0) = 0`，从 0 到 100 点能力增加约 9.09 点抗性，从 100 到 200 再增加约 7.58 点。抗性输出保留 `double` 精度，显示时才舍入。[抗性曲线与取整依据](https://github.com/NagiYume/AKEDatabase/blob/main/public/CH/research/终末地数据机制导论.md#112抗性区)

例如，主敏捷、副力量的角色从 100 敏捷增加到 110，物理抗性由约 9.09 变为 9.91 点，能力攻击加成同时增加 5 个百分点。单独增加 10 力量会增加 50 点最大生命和 2 个百分点的能力攻击加成。这个角色增加意志时仍能提高受治疗效率

### 2.2 固定计算顺序

沿用 `StatCalculator` 的全量重算。表中使用 Demo 默认系数，每项公式算出起始值后，对该目标应用一次第 3 节的词条和限幅。同一轮的下游公式读取已修正的上游值，整张面板校验通过后统一发布

| 顺序 | 计算 | 输入与输出 |
| --- | --- | --- |
| 1 | 四维及其他直接属性 | 从基础值开始计算各项最终值。能力公式读取四维最终值的整数部分 |
| 2 | `AttributeATKBonus = 主能力 × 0.005 + 副能力 × 0.002` | 只读取本角色选中的两项能力。加成经自身词条修正后供 ATK 读取 |
| 3 | `ATK = ((BaseATK + WeaponATK) × (1 + ATKPercentBonus) + FixedATK) × (1 + AttributeATKBonus)` | 固定攻击在普通百分比之后加入。ATK 自身的词条作用于整条公式的结果 |
| 4 | `DEF = BaseDEF`，以及第 2.1 节的四项固有收益 | MaxHP 读取 BaseHP 和力量，两种抗性和受治疗效率各读取对应能力。这五项结果都可以接受自身的 Modifier |

例如，100 敏捷提供约 9.09 点物理抗性。装备给敏捷加 100 点时，用 200 敏捷重新代入曲线，得到约 16.67 点。装备直接给物理抗性加 5 点时，从原来的约 9.09 点加到约 14.09 点。按各自的 `SourceID` 移除后恢复原值

**一笔可复算的攻击力**　基础攻击 100，武器攻击 200，固定攻击 50。角色主 INT 为 100、副 WIL 为 50，主副属性加成为 `100 × 0.005 + 50 × 0.002 = 0.60`

| 有效的攻击力加成来源 | 计算 | 最终 ATK |
| --- | --- | ---: |
| 装备 A 提供 +30% | `(300 × 1.30 + 50) × 1.60` | 704 |
| 装备 A，加上 Buff B 的 +20% | `(300 × 1.50 + 50) × 1.60` | 800 |
| Buff B 到期，装备 A 继续生效 | `(300 × 1.30 + 50) × 1.60` | 704 |

## 3. Modifier 与来源

### 3.1 词条与计算顺序

每条词条指定一个已登记的 `StatId`、一种操作和一个数值。所有属性共用下表。起始值 `B` 对直接属性取基础值，对派生属性取第 2 节的公式结果。`SetBase` 只修改直接属性

| 顺序 | 操作 | 对目标属性的作用 |
| --- | --- | --- |
| 1 | `Flat` 固定加值 | 在 B 上加全部 Flat 之和，单位与目标相同。对比例属性，+0.20 表示增加 20 个百分点 |
| 2 | `AdditivePercent` 同区百分比 | 将上一步结果乘以 `1 + 所有 AdditivePercent 之和`。两个 +20%、+30% 使 100 变为 150 |
| 3 | `Multiplicative` 独立倍率 | 将上一步结果乘以所有倍率的乘积。×1.20、×1.30 使 100 变为 156，×0 可使本步结果归零 |
| 4 | `Override` 覆盖值 | 有覆盖时取最高优先级的值。同一目标的同一优先级发生冲突时，拒绝整笔写入。移除胜出来源后，下一优先级生效 |

前三步合起来是 `(B + ΣFlat) × (1 + ΣAdditivePercent) × ΠMultiplicative`。没有词条的加法项取 0，乘积取 1。第 4 步完成后，统一按属性的 Minimum 和 Maximum 限幅。首批属性保留小数，显示精度由面板决定

下面两列是独立的计算用例，每次从同一初值出发，分别施加一条装备或 Buff 词条

| 目标与初值 | `Flat +0.20` | `AdditivePercent +0.20` |
| --- | ---: | ---: |
| `ATKPercentBonus = 0.30` | 0.50 | 0.36 |
| `ElectricDMGBonus = 0`（候选元素示例） | 0.20 | 0 |

### 3.2 来源替换与移除

在一个 `StatSet` 内，每个 `SourceID` 唯一标识一个实际装备或效果实例，例如 `Equipment/17`、`Effect/42`。同一角色上两个同模板 Buff 分配不同 ID，刷新某个实例时沿用原 ID。每个角色按来源持有整组词条

`ReplaceSource` 整组替换该来源。`RemoveSource` 和传入空列表的 `ReplaceSource` 都从候选集合中删去整个来源，按剩余词条重新求值。每次提交前应用以下数值规则

1. **校验新输入**　创建角色时检查基础值与公式系数，写入时检查本次提交的基础值或词条操作数。它们必须是有限的 `double`，`Multiplicative` 只接受非负倍率。首版以倍率乘积及其计算结果均可用 `double` 表示为上限
2. **计算实际面板**　按第 2 节和第 3.1 节顺序计算。检查累计和、倍率乘积、乘上该倍率后的结果及派生公式的中间结果。出现非有限值立即拒绝，检查发生在 Override 和限幅之前
3. **有零倍率时额外试算一次**　候选集合含 `Multiplicative ×0` 时，用同一计算器把所有这类操作数临时当作 1，重新计算整张面板，沿用相同的有限性检查。这样能发现零倍率盖住的乘积溢出，也能发现上游属性恢复后在下游公式中触发的溢出。这次试算不写缓存、不发通知
4. **提交**　所需计算均通过后，提交候选基础值、来源和按真实倍率算出的面板。`SetBase`、来源刷新和移除都按操作后剩余的词条执行上述计算。失败时指出发生溢出的属性或具体输入错误

例如 `DEF = 100`，来源 A 将 DEF 乘以 0。此时加入 ×2，实际 DEF 仍为 0，试算得到 200，可以登记来源 B。若提交的是 `double.MaxValue` 倍，倍率本身有限，但 `100 × double.MaxValue` 已经溢出，系统会在这次写入返回失败。两种来源到期后的实际读数见第 5.1 节

V1.3 两个入口统一返回 `StatWriteResult`，沿用 `Success`、`Error` 并增加 `RemovedEntryCount`。计数只表示本次成功整组移除的词条数

| 操作与结果 | Success | Error | RemovedEntryCount |
| --- | --- | --- | ---: |
| 成功提交非空替换，或重放相同替换 | true | 空 | 0 |
| 成功整组移除含 N 条词条的来源 | true | 空 | N |
| 移除不存在的来源，或再次移除 | true | 空 | 0 |
| 替换或移除失败，如未知操作、覆盖冲突、重算溢出 | false | 具体失败原因 | 0 |

失败时保留调用前的来源和面板，通知次数不变。调用方通过 `Success` 区分失败与成功移除 0 条

### 3.3 木剑穿脱怎样改变攻击与生命

沿用第 2 节的 704 面板。为便于复验，取 `WeaponATK = 200`、`FixedATK = 50` 为测试初值，已有来源 A 提供 +30% 攻击力，同时取 `STR = 10`、`BaseHP = 100`。木剑是另一个来源 `Equipment/17`，两条词条分别为 `WeaponATK Flat +3` 和 `STR Flat +3`。这些是演示输入，实际角色和武器数值由对应配置给出

| 操作 | WeaponATK / STR | ATK | MaxHP |
| --- | --- | ---: | ---: |
| 穿戴前 | 200 / 10 | 704 | 150 |
| 穿上木剑，一次 `ReplaceSource` 提交两条词条 | 203 / 13 | 710.24 | 165 |
| 卸下木剑，一次 `RemoveSource` 撤销该实例 | 200 / 10 | 704 | 150 |

角色主 INT、副 WIL，所以 STR +3 贡献 15 点 MaxHP。ATK 的增量全部来自武器攻击，等于 `3 × 1.30 × 1.60 = 6.24`。穿上和卸下各产生一次变更通知，每次回调都能读到该行完整面板，来源 A 在两次操作中持续生效

## 4. 面板更新与公开接口

在 Unity 主线程创建和更新角色面板。一次写入按候选来源全量重算，含零倍率时按第 3.2 节额外试算。成功后只提交一份实际面板，将有变化的属性及其旧值、新值合并为一次通知。数值相同仍登记有效来源，通知次数为零。订阅者在回调里即可读到完整的新面板

| 入口 | 调用约定 |
| --- | --- |
| `StatCatalog.Get(StatId)` | 静态查询，返回单个已登记属性的只读定义 |
| `StatCatalog.GetByGroup(StatGroup)` | 静态查询，按 StatId 顺序返回该组已登记的只读定义。空组返回空序列 |
| `StatCatalog.CreateSet(…)` | 实例方法，使用该资产的三项公式系数及传入的角色初值、主副属性创建角色面板 |
| `StatSet.Create(…)` | 直接接收角色初值、主副属性和系数，计算初始面板。纯数值测试可传入内存数据 |
| `StatSet.GetValue(StatId)` | 从缓存读取该属性的最终值。角色属性 UI 通过 `IReadOnlyStatSet` 读取，Damage 在动作约定的时点复制结算所需的数值 |
| `StatSet.SetBase` | 更新一项直接属性的基础值。写入派生属性、非法数值或导致重算溢出时返回失败 |
| `StatSet.ReplaceSource` | 装备或效果提交某实例的全部词条，按第 3.2 节返回 `StatWriteResult` |
| `StatSet.RemoveSource` | Effects 在 Buff 到期时撤销该来源，通过 `StatWriteResult` 读取成功状态与移除条数，或失败原因 |
| `StatSet.Subscribe` | 订阅已发布的面板变化，可解除订阅。Resources 读取 MaxHP 并自行决定如何调整 CurrentHP |

**角色属性 UI 的读取与刷新**

1. 打开某名角色的属性页时，按组调用 `StatCatalog.GetByGroup(StatGroup)` 取得属性定义。对每个已登记的属性调用该角色的 `IReadOnlyStatSet.GetValue(id)`，填入对应行
2. 页面打开期间订阅该角色的 `Subscribe`。收到 `StatChange` 后，按 `StatId` 将该行更新为 `NewValue`。最终值相同时无需刷新。关闭页面或切换角色时解除旧订阅

例如第 3.3 节的角色穿上木剑后，界面中的三行如下。木剑的词条及其 `SourceID` 由 `StatSet` 持有，供穿脱和重算使用

| 分组 | 属性 | 最终值 |
| --- | --- | ---: |
| 基础属性 | 力量 | 13 |
| 基础战斗 | 武器攻击 | 203 |
| 战斗面板 | 最大生命 | 165 |

V1.4 使用相同的 `GetByGroup`、`GetValue` 和 `Subscribe`。以现有 Phoebe 初值为例，AGI 0、INT 100、WIL 50 时，抗性组的两行分别显示「物理抗性　0」「法术抗性　9.09」，特殊属性组显示「受治疗效率　5%」。UI 继续只显示属性名和最终值

一次更新的边界是一项基础值或一个来源。两次独立调用各自生效。Damage 保存单次攻击的取值，Stats 只维护角色当前面板

**V1.3 的接口变化**　所有已登记属性共用四种操作。`ModifierOperation` 保留原有四个枚举数值，`AttributeATKBonus` 应用自身词条后将最终值传给 ATK 公式

`RemoveSource` 和空列表 `ReplaceSource` 均返回 `StatWriteResult`。调用方先检查 `Success`，再读取 `RemovedEntryCount` 或 `Error`。零倍率下的非法写入会在登记前被拒绝，正常到期行为见第 5.1 节。[运行时入口](../Assets/Scripts/Runtime/Stats/Runtime/StatSet.cs)
