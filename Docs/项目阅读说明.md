> 当前活动工程仅包含 P1，更新于 2026-11-18

## 1. 阅读顺序

| 顺序 | 源码入口 | 重点 |
|---|---|---|
| 1 | `Assets/Scripts/Runtime/Input/GameInputManager.cs`、`Character/PlayerController.cs` | 帧输入快照、捕获/暂停、相机方向转移动意图、攻击请求 |
| 2 | `Combat/CombatSimulation.cs`、`Combat/CombatRulesDefinition.cs` | 每帧预算、每步顺序、单次移动、命中排序、延后结果 |
| 3 | `Combat/Input/CombatInputBuffer.cs` | 输入帧去重、序号、过期和成功后消费 |
| 4 | `Character/CharacterDefinition.cs`、`Character/Combatant.cs`、`Character/Stat/` | 三属性和普攻共享配置、角色状态、生命与内部死亡 |
| 5 | `Combat/Actions/ActionDefinition.cs`、`ActionRuntime.cs`、`ActionController.cs` | 定义与实例、执行 ID、点/窗口时序、自然结束和取消清理 |
| 6 | `Combat/Actions/ComboController.cs` | 普攻数组、推进点、取消窗口和输入缓存共同决定接段 |
| 7 | `Animation/AnimationPlayer.cs`、`Animation/AnimationPlayback.cs`、`Animation/AnimatorRootMotion.cs`、`Character/Movement/` | Playables 手动求值、根增量与 Motor 统一移动 |
| 8 | `Combat/Weapons/WeaponController.cs`、`Combat/HitDetection/`、`Combat/Resolution/CombatResolver.cs` | 指定骨骼挂载、武器前后姿态、窗口交集与分段查询、两层去重、伤害和死亡顺序 |
| 9 | `Combat/TargetingController.cs`、`Combat/Animation/MotionWarping.cs`、`RootMotionDefinition.cs` | 辅助选敌、窗口锁定、根轨迹修正、碰撞后停止贴近 |
| 10 | `Presentation/CombatFeedbackPlayer.cs`、`UI/CombatHUD.cs`、`UI/GameUIController.cs` | 池化音效/粒子与局部事件，木桩/连段 HUD 和三属性面板 |
| 11 | `Assets/Scripts/Editor/Combat/` | Inspector、Timeline 轨道编辑、隔离预览和实际 Avatar 根轨迹烘焙 |

表中从第二列 `Character/`、`Combat/` 等开头的路径均相对于 `Assets/Scripts/Runtime/`。框架入口只有当前所需职责，没有通用 NotifyRunner、全局事件总线、技能提交层或行为树运行时。

项目自定义 SO 资源统一位于 `Assets/ScriptObjects/`：`Characters/` 保存角色配置，`Combat/Actions/`、`Combat/RootMotion/`、`Combat/Rules/` 保存战斗定义，`Presentation/` 保存表现配置。Timeline 验证资源位于 `Tests/Editor/TimelineFixture.asset`，对应的验证代码仍在 `Assets/Tests/Editor/`。

读普通移动时，从 `PlayerController.Update` 开始。它先把鼠标输入交给 `CustomThirdPersonCamera.ApplyLook`，再按本帧镜头水平朝向换算 WASD 的世界方向。`CharacterMotor.UpdateLocomotion` 根据走跑意图更新 `LocomotionSpeed`（米/秒）与朝向，两者给出候选位移 `LocomotionDelta`（米）。`CombatSimulation.MoveUnits` 选择本步位移来源，Motor 叠加重力、调用一次 `CharacterController.Move`，记录请求与实际水平位移。相机在自己的 `LateUpdate` 中跟随角色并处理避障。

移动状态只保留 `Character/Movement/LocomotionStateId.cs` 枚举，Idle/Walk/Run 选择直接在 Motor 中完成。动画入口是 `Runtime/Animation/AnimationDefinition.cs`。`pointEvents` 保存瞬时事件，`windowEvents` 保存有起止时间的事件。`PresentationEvents.cs` 定义声音和特效，`CombatTimelineEvents.cs` 定义连段、取消与命中，`MotionWarpWindow` 位于 `MotionWarping.cs`。

## 2. 一次攻击的真实调用链

`GameInputManager.Update` → `PlayerController.Update` → `AttackRequested(frame)` → `CombatSimulation.QueueAttack` → `CombatInputBuffer`

战斗步由 `CombatSimulation.SubmitPlayerAction` 读取队首攻击和玩家当前的 `WorldMove`，交给 `ComboController.TryAttack`。空闲从首段起手，接段在推进点和取消窗均许可时取下一索引，末段回到索引 0。每一刀由 `SelectAttackTarget()` 在角色周围水平 3.5 米内全向选择最近的合格敌人。选中时朝目标出刀，空挥时按 `WorldMove` 决定方向。获准后 `ActionRuntime.InitializeOpeningFacing` 记录朝向差并返回首帧朝向。Motor 先应用朝向，`AnimationPlayer.StartPlayback` 再建立初始姿态。编辑器 `ActionPreview.SetTarget` 也用这个返回值作为预览轨迹的首帧。`openingTurnDuration` 以片段秒计，设为零时立即应用起手朝向。模拟器随后消费这一条输入，再派发零时刻通知。攻击未获准时继续检查移动取消，缓存仍按战斗时间过期。

普通角色通过 `AnimationPlayer.Play(animation)` 播放同一动画资产。战斗角色由 `ActionController.TryStart` 提交动作，`ActionRuntime` 将自身作为本次播放的战斗接收者。独立角色在 `AnimationPlayer.Update` 中依次调用 `AnimationPlayback.Advance(step)`、`EvaluatePose(step)` 和 `DispatchEvents(playback)`。战斗角色由 `CombatSimulation` 按战斗步驱动同一套播放时钟与姿态采样，动作执行通过 `ActionRuntime.Advance(step)` 先清空本步区间。动画从 0 播放到 `clip.length`。接招时 `AnimationPlayer.StartPlayback` 记录 Mixer 各输入的可见权重，新片段按自己的缓入接手。取消回走跑时 `EndPlayback` 记录当时的混合比例，按离场片段的缓出返回移动。自然收招已开始时继续原过渡。

动作和根轨迹配置直接读取，不在初始化或每次起手时扫描校验。根轨迹依赖签名只用于编辑器提示重新烘焙；窗口范围、引用和模型匹配由开发者维护。

根轨迹直接引用已有 `Phoebe.fbx`，签名包含采样率。`RootMotionDefinition.Sample` 以已烘焙样本的时间戳定位区间，输入参数待重烘焙时仍可查询原轨迹。预览循环在编辑器 `ActionPreview` 内，按播放倍率和 Timeline 的整数 FPS 确定局部采样间隔。实战和预览在起手选敌及各窗口进入时共用 `IsWithinAssistance` 的水平距离和高差判断，窗口内按配置限制速度、修正角与转向角速度。

每个战斗步先处理延后取消和玩家指令。`UpdateActionsAndAnimation` 先推进动作时钟。`AnimationPlayback.Advance` 对命中窗和扭曲窗直接取本步与窗口的非空交集，交给各自的 `OnInterval`。有命中区间时保存武器起点，随后更新走跑参数，通过 `AnimationPlayer.EvaluatePose(step)` 将图采样至本步局部时间。`MoveUnits` 选择走跑、原地动作、扭曲轨迹或动画根增量，提交实际转向和移动，并为本步命中区间保存武器终点。随后推进战斗时钟、处理动作通知。`ResolveHits` 同步物理位置，收集、排序并结算命中。最后结束到期动作并发布结果。

`Animation/AnimationAnchorBindings.cs` 把事件中的 `AnimationAnchor` 解析为当前模型的 Transform。先读取 Inspector 中的节点绑定，再按部位读取模型根或 Humanoid 骨骼。音效点、特效点和特效窗口共用该入口，预览在克隆模型上解析。

`WeaponController.Awake` 把武器 Prefab 实例化到模型绑定的 `Weapon` 节点，建立 `id → Hitbox` 缓存。`HitWindow.hitboxIds` 选择检测体，`group` 控制一次动作的伤害去重；几何配置在武器 Prefab 上。`HitDetection.Collect` 按本步收集的精确交集调用 `Hitbox.Query`，后者统一处理姿态插值、分段物理查询、缓冲扩容与接触点计算。返回的 `HitboxContact` 只包含碰撞体与接触点；目标筛选、遮挡、批次去重和请求收集在 `Collect` 中顺序完成，扣血仍由 `CombatResolver` 负责。Timeline 预览复用同一武器配置和几何计算，不执行物理查询。

目标使用普通 Collider：`targetMask` 筛选 `HitTarget` 层，`Collider.GetComponentInParent<Combatant>()` 查找角色。当前没有 Hurtbox 组件或 Owner 缓存；死亡只清理当前动作，检测与结算依据存活状态排除死亡角色，不遍历关闭受击组件。

`ActionController.End(executionId, reason)` 处理匹配执行的自然完成、取消与中断。结束时清空 `Current`，标记原 Runtime 已结束，归还其循环音效、跟随特效和持续窗口句柄，动画淡出，记录结束原因。旧执行 ID 不会取消新的动作。

表现对象的租借从 `GameObjectPool.Rent` 进入。实例在未激活时设置姿态，音源或粒子随后由 `Play` 配置并激活。归还时 `PooledObject.Return` 核对租借版本，调用子类的 `OnReturn` 清理播放状态，再停用实例并恢复初始缩放。

`Combatant.Awake` 订阅 Motor 和动画播放器的 `Disabled` 通知，任一组件停用都由角色发起动作中断。模拟器订阅玩家控制器的 `Disabled` 通知，以便立即清空输入缓存。玩家控制停用只清理输入；动作组件停用仍允许普通移动；动画或 Motor 停用中断动作并停止相关模拟。`useRootMotion` 统一控制动作根平移、根旋转与扭曲，关闭后仍保留骨骼挥击和碰撞重力。

## 3. 时间与通知的调试位置

- 输入没有触发：先看 `GameplayCaptured`、当前帧快照及缓存序号；第一次点击只捕获控制，暂停会清空攻击缓存
- 无法接段：同时检查 `ComboAdvanced`、当前攻击取消窗口、缓存是否过期；不要只看动画是否仍在播放
- 点通知重复/缺失：看 `ActionRuntime.Playback.NextPoint`、`LocalTime` 和动作执行 ID
- 命中不生效：依次看 WeaponController 挂点/Prefab、Hitbox ID 与有效世界尺度、窗口交集、真实刀刃轨迹、targetMask/worldMask、Collider 父级 Combatant、阵营、遮挡、runtime.hits、来源/目标当前状态
- 动画与移动不一致：看 `ClipTime`、`PreviousTime/LocalTime`、动画根增量和 Motor 的请求/实际位移；角色根位置只由 Motor 提交
- 扭曲异常：看选中目标、`WarpState`、源烘焙签名、窗口是否覆盖整个前进段、站位安全检查与 `ObserveCollision`
- UI 结果晚于扣血：这是步末发布设计；内部生命和死亡清理先完成，外部订阅之后执行

窗口不是普通每帧“当前时间在里面就触发”的单一模型：命中读取经过区间，取消读取提交时刻，效果记录进入状态，扭曲按窗口片段求增量。具体契约见实现文档第 4 节。

## 4. 运行与编辑验证入口

`Assets/Tests/Scenes/` 保留动画技术验证，以及 Entry、Action、Hit、Combo、Scene、Warp 六个 P1 场景。各场景中的 `Combat*Probe` 使用已有最小断言检查关键路径；正常输入场景需要 Game View 获取焦点。

`Endfield.EditorValidation.CombatTimelineValidation.Run()` 检查实际 IMGUI 拖动、吸附、Undo/Redo、保存重导入；`CombatWarpEditorValidation.Run()` 检查烘焙签名、预览、目标拖动和释放。调用会写入 `Logs/`，时间与结果以本次日志为准。

独立 Unity 批处理使用 `CombatEntryBatch.Run`、`RunActions`、`RunHits` 或 `CombatValidationBatch.RunAnimationProbe` 打开已有验证场景，结果写入 `Logs/` 后退出。工作编辑器可直接打开对应验证场景。`CombatEntryBatch.RunDemo` 直接打开正式 `Assets/Scenes/CombatDemo.unity`，验证主角胶囊尺寸、一次真实普攻伤害及 HUD 两处文本更新。

`CombatDemoSetup.ConfigureCombo` 补建缺失动作时复用已有动画和根轨迹，只为新动画写入默认事件。空普攻列表初始化为三段，有配置的列表只补已有长度内的标准空槽。

当前可游玩入口为 `CombatDemo`，没有旧的四人遭遇或自动通关驱动。测试木桩死亡后重新进入 Play Mode 即可恢复。实际验证结果及未覆盖边界集中在实现文档第 8 节。
