## 2. 开始测试

1. 打开 `Assets/Scenes/CombatDemo.unity`，进入 Play Mode，点击 Game View 捕获鼠标；首次点击用于捕获控制
2. `WASD` 移动、`Shift` 跑步、鼠标转镜头。左键普攻在前摇内转向附近最近的可辅助敌人。身边没有合格目标时按移动方向空挥，松开方向键则沿原朝向出刀
3. 接段窗口内再次点击可连续打出 `1 → 2 → 3 → 1`。略早的按键可在 0.2 秒缓存内等候开窗，停止点击后当前段自然结束
4. `C` 打开三属性面板；面板打开期间战斗暂停，`Esc` 关闭并恢复之前的控制状态
5. 普通游戏状态按 `Esc` 释放鼠标并暂停战斗，再点击 Game View 恢复
6. 木桩死亡后显示“已击破”，命中与结算通过存活状态排除死亡角色；重新测试时退出并重新进入 Play Mode

P1 没有重开、技能、闪避、切人或锁定按键。玩家当前攻击 100、最大生命 1000、防御 20；木桩最大生命 1000、防御 50。木桩没有 AI 和攻击动作。

## 3. 模块与状态归属

| 模块 | 当前职责 |
|---|---|
| `GameInputManager` / `PlayerController` | 每渲染帧采样输入，将移动转换到世界方向，通过局部事件提交攻击按键的帧号 |
| `CombatSimulation` / `CombatRulesDefinition` | 持有攻击缓存，在战斗步内裁决攻击与移动取消，成功起手后消费输入并派发零时刻事件。负责时间预算、单位编号、命中排序及结果发布。规则资产配置步长、缓存和检测层 |
| `CharacterDefinition` / `Combatant` | 共享三属性与普攻顺序配置；角色实例持有 Stats、Health、Motor、Animation、Actions、Combo、Targeting |
| `AnimationDefinition` | 保存片段、倍率、缓入和缓出曲线及各自时长，以及两组可序列化的时间轴事件 |
| `ActionDefinition` | 引用动画，配置动作类别、起手转向时长、根运动开关及根轨迹 |
| `AnimationPlayback` | 保存每次播放的倍率、局部时间、点游标、窗口状态、资源句柄和可选战斗接收者。`Advance(step)` 按倍率推进并截到片尾 |
| `ActionRuntime` | 每次战斗执行的 ID、目标、连段和取消许可、命中集合、扭曲状态及本步的有效区间 |
| `ActionController` / `ComboController` | 动作提交与推进，通过 `End(executionId, reason)` 结束匹配执行。连段依据普攻数组、推进点和取消窗口决定下一段 |
| `AnimationPlayer` / `AnimatorRootMotion` | 手动 PlayableGraph 求值，移动/新旧动作混合，收集根增量；不直接移动角色根对象 |
| `CharacterMotor` | 规划普通移动；统一提交旋转、水平位移、重力和碰撞，记录实际移动结果 |
| `WeaponController` / `Hitbox` | 在指定骨骼挂点创建武器 Prefab，缓存 ID 与检测体；Hitbox 保存姿态和几何，并完成分段空间查询 |
| `HitDetection` | 截取有效窗口、调用 Hitbox.Query，通过普通 Collider 的父级查找 Combatant，筛选目标与遮挡、合并同组候选并产生 HitRequest |
| `CombatResolver` / `CharacterHealth` | 最终去重、伤害与扣血、内部死亡清理；对外生命/命中结果延后通知 |
| `TargetingController` / `MotionWarping` | 起手选近距可辅助目标，按窗口修正烘焙轨迹，接受 Motor 阻挡反馈 |
| `CombatFeedbackPlayer` / `CombatHUD` | 复用原有池化音效与粒子；显示命中和木桩生命，没有全局事件总线 |

项目自行编写的 SO 类型统一使用 `Definition` 后缀。保留旧资源实例名，例如 `PlayerCharacterAsset.asset`，不因此更换资源 GUID。

项目自有字段统一使用 camelCase，类型、方法和属性保持 PascalCase。已有动作、窗口、规则和根轨迹资产直接迁移到新字段名，编辑器属性查找和测试调用同步更新，不保留旧名称兼容标记或重复入口。字段改名只改变存储名称，配置值、资源 GUID、片段子资源引用和烘焙样本保持不变。

动作配置由开发者维护，运行时直接使用。`ActionDefinition` 只描述数据，初始化、起手和预览前均不执行全量配置校验，也不预扫描窗口、挂点或模型匹配情况。`TryStart` 在一个方法内完成业务条件判断、创建运行时、替换旧动作、播放和记录结果；死亡、取消条件、目标失效及执行 ID 检查仍按实际状态执行。

场景和对象池同样直接读取内部配置；移除整批配置扫描、重复的 Inspector 数值修正及内部参数预检。组件初始化、对象销毁、池化版本、目标状态和动作生命周期检查按实际用途保留。输入初始化、Motor 的速度/转向规划与移动/碰撞反馈各自在连贯方法内表达；运动扭曲的源轨迹计算返回位移与朝向，Timeline 点排序复用标准库的稳定排序。

`CharacterMotor.UpdateLocomotion` 更新走跑状态、速度和朝向。`LocomotionSpeed` 驱动移动动画，`LocomotionDelta` 是本步走跑候选位移。`MoveUnits` 最终选用走跑、零位移、扭曲轨迹或动画根增量，Motor 统一处理重力和碰撞，每步提交一次。Motor 停用与重新启用时清空运动状态。相机在 `CustomThirdPersonCamera` 内保存 yaw、pitch 和跟随角色，在 LateUpdate 更新观察点与避障距离。

玩家控制器停用时归零移动意图，模拟器收到通知后立即清空攻击缓存，已起手动作继续推进。ActionController 停用时取消动作并拒绝新动作，普通移动可继续；Combatant 订阅 Motor 与 AnimationPlayer 的停用通知。任一组件停用或角色自身停用时，由角色中断动作并停止相关模拟。动画停用先请求动作清理再释放图，延后取消不依赖已销毁的图。角色对象重新启用不恢复旧执行。静止木桩仍无需移动和动作组件，禁用 CombatSimulation 后仍可显式调用 `AdvanceFrame` 验证。

## 4. 时间步与完整执行流程

每渲染帧按未缩放时间计算：先处理暂停/剩余顿帧，再乘战斗倍率；最大子步为 1/60 秒，每帧最多 4 步。超预算部分直接截断，下一帧不追赶。`Now` 仅累计实际执行的步长。顿帧目前只是时间入口能力，P1 未接入自动命中顿帧表现。

每个战斗步按以下顺序执行：

1. 清除过期攻击缓存，执行上一步结果回调提出的动作结束请求
2. 模拟器用当前移动方向尝试攻击，成功后先消费输入，再处理零时刻事件。攻击未提交时检查移动取消
3. 普通播放调用 `AnimationPlayback.Advance(step)`，动作通过 `ActionRuntime.Advance(step)` 清空并收集本步命中和扭曲区间。有命中区间时先保存武器起点，再更新走跑参数并用 `AnimationPlayer.EvaluatePose(step)` 按当前局部时间采样姿态
4. 根据走跑、根增量或扭曲结果计算位移，由 Motor 统一提交。有命中区间时保存武器终点
5. 累加战斗时钟，处理经过的点通知和持续效果窗口
6. 同步物理 Transform；收集命中请求，按来源 ID、执行 ID、命中组、目标 ID 排序
7. 逐条结算、立即做内部死亡清理；处理动作自然结束
8. 最后发布动作、生命、属性与命中结果；发布期间拒绝新动作提交，结束请求延到下一步。订阅回调抛出异常时结束本批发布并传播异常，未尝试及新排入的通知留到下一步，已尝试的通知不会重播

`AnimationDefinition` 内嵌 `TimelinePointEvent[]` 和 `TimelineWindowEvent[]`，两组均通过 `[SerializeReference]` 保存具体类型。每次播放由 `AnimationPlayback` 独立推进。命中和扭曲这两种移动前窗口只接收 `OnInterval`，步端恰好触及窗口时交集长度为零，只有正长度的重叠才会提交。

- 点通知：按时间排序，通过 `NextPoint` 游标处理所有 `Time <= LocalTime` 的未处理点；每次执行只触发一次，包含零时刻与动作结束点
- 命中窗口：取 `[PreviousTime, LocalTime]` 与窗口的有效交集；截取武器前后姿态并分段查询，完整跨过短窗口也会执行检测；空间精度边界见下节
- 取消窗口：进入时登记、退出时移除，持有当前 `[start, end)` 内所有窗口分类的并集
- 持续效果窗口：按时间边界执行进入/退出；同一步跨过整个窗口时先进入再归还；取消、死亡、停用均归还该动作自己的句柄
- 扭曲窗口：对经过的窗口片段求源轨迹增量与有限修正，不用渲染动画事件决定玩法时序

同一时刻的点按连段、音效、其他点稳定排序。`ComboAdvancePoint`、`CancelWindow`、`HitWindow` 和 `MotionWarpWindow` 只向当前战斗执行提交状态或区间。`AudioPoint`、`EffectPoint`、`EffectWindow` 在动画资产上保存挂点枚举、局部偏移和表现配置。播放时从本角色模型解析目标，跟随特效持有本次解析的 Transform。一次播放结束时立即结束窗口，回收归属它的表现句柄。旧片段仍可在混合图中淡出。

`openingTurnDuration` 为每个动作的可序列化片段秒数，三段普攻均为 0.38。运行时与轨迹预览共用 `ActionRuntime.InitializeOpeningFacing`。有水平方向时，零时长立即转到出刀朝向，正时长从原朝向逐步转身。无水平方向时沿用原朝向。每步先用 `PreviousTime` 恢复根轨迹的朝向，再用 `LocalTime` 计算可见朝向和位移。缓入、缓出也使用片段秒，各自拥有曲线。三段普攻的缓入和缓出分别迁移为 0.42、0.28、0.70，在原 1.4 倍率下对应 0.30、0.20、0.50 秒。接招时新刀按自己的缓入取得权重，其余片段和走跑按切换时的可见比例分享余量。取消回走跑采用离场动作的缓出，若已进入自然收招，沿用当时的过渡进度。退出片段在淡出期间继续播放至多到片尾。独立角色没有基础移动时首次直接显示片段并在自然结束后保留末帧。战斗角色的播放及过渡随模拟暂停和命中停顿冻结。

三段普攻采用有序数组。推进点已触发且攻击取消窗口开放时，新按键用 `(当前索引 + 1) % 段数` 选择下一段，允许空挥衔接。成功接段优先于同一步的移动取消，旧动作以 `Cancelled` 结束，新动作获得新的执行 ID。每段获准时读取最新 `WorldMove`，从上一段的实际朝向平滑转入新方向。

## 5. 命中、生命与反馈

P1 已改为武器骨骼驱动的球/胶囊 Hitbox，不再使用角色前方大球体。当前武器是 `Assets/Prefabs/Weapons/GreatSword.prefab`，包含 `Visual` 和 `BladeHitbox`；Hitbox 是查询几何，不需要 Rigidbody 或 Collider，不依赖 `OnTriggerEnter`。

`Player.prefab` 根对象上的 `WeaponController` 引用模型上的 `AnimationAnchorBindings` 与武器 Prefab。绑定表中的 `Weapon` 指向原有的 `WeaponSocket_R`，装备与表现使用同一节点。进入运行时创建武器，缓存 Hitbox ID；换装先关闭旧实例再销毁，并重新建立采样。已有骨骼世界缩放为 100，挂点以 0.01 抵消；武器和 Hitbox 的有效世界缩放为 1，原握持旋转与外观尺度保持一致。武器实例仅在 Play Mode 或隔离动画预览中创建。

配置方式：

1. 在 Animator 所在物体添加 `AnimationAnchorBindings`。在 Bindings 中选 `Weapon`，将模型层级里的武器挂点拖到 Target，再给 `WeaponController` 指定该组件和武器 Prefab。动画的 Anchor 默认选模型根节点。左右手、左右脚、头、髋、脊柱优先使用显式绑定，省略绑定时使用当前 Humanoid Avatar 的对应骨骼；普通骨架可直接拖入 Transform。
2. 在武器 Prefab 下添加 Hitbox 子对象；设置唯一 `id`、`shape`、`center`、`radius`、`length` 和 `axis`。胶囊 `length` 是两个端部球心的距离，半径按世界最大轴缩放，非均匀缩放采取保守包围
3. 动作 `HitWindow` 保存 `start/end/group/damageMultiplier/hitboxIds`；几何只在武器上配置。相同组的多个 Hitbox 共享一次伤害，不同伤害段使用不同组
4. Timeline 选中命中窗口，勾选预览武器中的检测体；选中武器 Hitbox 可在 Scene/Prefab 视图显示 Gizmos

当战斗步与命中窗口相交时，在动画求值前采样挂点位置、旋转和缩放，在 Motor 完成真实位移后再次采样。窗口只读取这份样本，不在逐窗口检测时更新历史。按窗口交集插值位置、旋转和缩放，再按平移距离、旋转弧长和缩放变化分段调用 `OverlapCapsuleNonAlloc` / `OverlapSphereNonAlloc`；缓冲满时扩容并重新查询。查询通过 `CombatRulesDefinition.targetMask` 筛选普通 Collider，再用 `GetComponentInParent<Combatant>()` 找到所属角色。当前玩家和木桩的 `Body Collider`、`Head Collider` 保留原触发器形状，位于 `HitTarget` 层（索引 10）；不再挂受击组件或缓存 Owner。查询显式使用 `QueryTriggerInteraction.Collide`。遮挡从 `Combatant.hitOrigin`（默认身体上方 1 米）到接触点检查 World 层。

空间查询集中在 `Hitbox.Query(startFraction, endFraction, layerMask)`：参数是有效窗口在本步内的起止比例，返回碰撞体与接触点组成的 `HitboxContact`。Collider 缓冲和结果列表由 Hitbox 复用，调用方在下一次查询前消费结果。`HitDetection.Collect` 连续完成窗口截取、查询、目标筛选、遮挡、批次去重和请求收集，不再通过传递大量参数的 `AddCandidate` 处理单个候选。检测与结算仍保持分离，采样密度、窗口语义和伤害规则保持不变。

每步最多插值 32 段。这是已有真实骨骼姿态之间的近似扫掠，不是连续碰撞检测，也不能还原两次求值之间未采到的动画弧线；高速移动目标仍按本步结束姿态查询。极高速动作需要进一步增加真实姿态/相对运动采样，不能仅增加插值点就保证不漏检。瞬移应在战斗步入口前完成；有命中区间的步重新捕获起点，避免把瞬移距离当成挥击。

三段大剑窗口按主挥击重新定位，均使用 `BladeHitbox`（ID 0），倍率保留 0.8 / 1.0 / 1.8：第一段 `[0.60, 0.89)` 秒，第二段 `[24/60, 31/60)` 秒，第三段 `[0.95, 1.30)` 秒。起手选敌范围只是运动辅助范围，不保证刀刃能打到该范围内的所有目标。

检测阶段先做单批次去重，结算阶段以“当前执行 ID 对应的 Runtime + 命中组 + 目标 ID”记录已结算目标。多个 Collider、连续帧或同组窗口对同一目标只结算一次。动作取消、来源死亡、目标死亡/停用会令后续请求失效。

伤害公式：`max(0, Attack × DamageMultiplier) × K / (K + max(0, Defense))`，当前 `K = 100`。不包含暴击、元素抗性、护盾、异常或资源奖励。

生命改变立即更新内部状态；死亡立即取消当前动作，再延后发送 UI 等外部通知。角色不缓存或遍历受击组件，也不因死亡统一关闭普通 Collider；检测与结算通过 `Health.IsDead` 拒绝继续命中死亡角色，身体碰撞保持原配置。已有生命治疗方法属于原有基础能力，P1 没有治疗技能系统。

HUD 订阅动作、命中和生命通知更新文字，每帧仅跟踪目标的屏幕位置和可见性。循环音效点与跟随特效由动作保管池句柄，完成或中断时一并归还。单次音效播放完毕后自行归还。动作配置支持音效点、粒子点及持续效果窗口，复用现有对象池；它们不是自动生成的全套命中特效配置。

## 6. 运动扭曲与动作编辑

三个普攻均保留对应根轨迹资产和扭曲配置。直接使用已有 `Phoebe.fbx` 的实际 Avatar 与尺度、60 Hz 顺序采样烘焙根轨迹，不再维护专用模型 Prefab。签名包含动画依赖、模型依赖、尺度和采样率，并使用稳定数值格式；这些内容变化后由 Inspector 提示重新烘焙。`Sample` 按已保存样本的时间戳二分查找并插值，越界查询取首末样本。新的烘焙结果一次性替换采样数据、Avatar 与签名。

`useRootMotion` 控制动画根平移、根旋转与扭曲修正。关闭时水平位移为零，普攻仍可按起手意图转身，Motor 继续处理重力和碰撞。开启且无扭曲窗口时使用动画图根增量；开启且有窗口时使用主动作烘焙轨迹及修正，两者不叠加。

普攻在水平半径 3.5 米内按 360° 选取最近的存活、启用且可见敌人，允许高差绝对值为 0.5 米以内。按住 S 时，正前方的敌人同样可以成为起手和扭曲目标。每段攻击在前 0.38 秒动作时间内平滑消除起手朝向差。身体背对出刀方向时暂缓水平推进，转正后使用完整增量。窗口内另外按配置进行有限修正，进入时复核距离和视线，检查站位并锁点。

第三段大剑在素材第 76～94 帧的收势步中逐渐将骨盆纵向偏移分配给根骨，最后双脚回到与待机接近的站位。对应根轨迹已重新烘焙。提前取消时，旧片段在淡出期间从当前权重继续播放至片段末尾，旧执行的命中与事件在取消时结束。

默认额外停止间距 0.15 米、最大贴近 2 米、额外延伸 1 米、最大速度 8 米/秒、修正角 60 度、角速度 720 度/秒。玩家半径 0.3 米、木桩半径 0.5 米；受到限制时允许无法到达理想位置。碰墙后停止本窗口的贴近修正，不累积被阻挡的距离等待补偿。

第一段扭曲窗口覆盖 `[0, 2.633333)`，第二、第三段的现有窗口覆盖至片段结束。角色在窗口内受贴近距离、速度和碰撞限制。贴近站位先检查地面，再按当前 CharacterController 的中心、高度和半径检查净空，胶囊底端预留 0.05 米地面接触余量。

双击动作资产、独立动画资产，或打开 `Window/Endfield/Action Timeline`：

1. 选择动画或动作与预览角色，播放、逐帧或拖动游标查看姿态、粒子和轨迹；预览按角色的武器配置挂载同一 Prefab
2. 在空白轨道拖动游标，拖动点通知或窗口边缘编辑时间。长度超过片段的窗口可修改边缘或显式对齐末尾，其余窗口还可整段平移
3. 命中窗口可勾选具名 Hitbox。灰色显示武器几何，橙色显示最近一个预览战斗步内的近似扫掠。「预览战斗帧率（FPS）」默认为 60，可提交 1～1000 的整数。逐动画帧和帧吸附使用 Clip 帧率。
4. 修改扭曲窗口和模拟目标，查看源轨迹与扭曲轨迹；需要时更新根轨迹烘焙
5. 点击“保存”，事件写入所选动画资产，所有引用者读取同一份时序

时间轴绘制、轨道选择、事件创建及拖拽验证共用 `TimelineTrack` 枚举，枚举顺序决定显示顺序。Inspector 和 Timeline 在提交编辑时按开始时间稳定排序扭曲窗口，提示窗口重叠，并可逐项将越过片段的结束时间对齐到片段末尾。打开资产不会改写已有窗口。切换轨道或动作会清除旧选择。时间轴拖拽保留范围限制、点通知排序和帧吸附；详细字段允许直接输入，由开发者维护配置关系，不另设全量保存校验。编辑器是隔离 Preview Scene，不执行真实伤害；关闭或预览失败时释放预览对象，预览异常不阻止保存。预览正确不等于战斗碰撞与动画衔接已验收。

角色、动作或片段切换时重新创建隔离预览。修改命中、取消、连段和音频事件时复用角色、武器、动画图和轨迹。扭曲参数、根轨迹烘焙、目标、播放倍率或预览 FPS 变化时重算轨迹，粒子事件变化时更新预览粒子。

Timeline 与默认 Inspector 共用具体通知类型的添加、独立复制和删除操作，选中项只显示本类型字段；更换类型通过删除后添加完成。排序后保留原条目的选择，复制不共享可编辑对象。预览采样循环位于 `ActionPreview`，每步采样的动作局部时间为播放倍率除以预览 FPS，并使用角色身体半径；模拟目标半径可配置，停止间距显示使用同一参数。水平距离与高差筛选复用 `TargetingController.IsWithinAssistance`；预览不代替实战的阵营、遮挡与地面检查。
