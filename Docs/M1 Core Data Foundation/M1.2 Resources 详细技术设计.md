### 1.1 谁持有哪一份数值

| 资源 | 运行时所有者 | 上限与进场值 | 后续调用方 |
| --- | --- | --- | --- |
| 当前生命 HP | 每个角色的 `CharacterResourceContainer` | 上限取自该角色的 Stats，进场时满血 | Damage 提交最终伤害，治疗结算方提交最终治疗量，Actors 处理生命归零后的角色行为 |
| 战技点 SP | `Combat Session` 上的 `TeamSkillPoints` 持有该队的 `SkillPointPool` | 最大值与进场值来自队伍组件，切换操控角色沿用同一池 | Skills 提交战技时扣费，产生技力的玩法调用恢复入口 |
| 终结技能量 | 每个角色的 `CharacterResourceContainer` | 上限与进场值来自该角色的资源配置 | Skills 只消耗释放者的能量，获取能量的玩法指定受益角色 |
| 失衡积累值 | 受击角色的 `CharacterResourceContainer` | 阈值来自角色资源配置，进场积累为 0 | 命中结算提交积累量，Status 决定进入、退出失衡及清槽时点 |

角色配置资产类型为 `CharacterResourceProfile`（ScriptableObject），序列化字段为 `maxUltimateEnergy`、`initialUltimateEnergy`、`staggerThreshold`

队伍在场景组件上配置 `maxSP`、`initialSP`，由该组件创建一个纯 C# 的 `SkillPointPool`。Skills 接入时，同队角色从这一个池扣费

运行时数值存入各自的容器，角色 Prefab 和配置资产只提供初值与容量

容量与进场值以点为单位，使用与 Stats 一致的 `double`，创建时检查数值有限、容量非负、进场值落在 `[0, 上限]`，报告有误的配置字段

HP 上限随 Stats 更新，其他容量在创建时确定，其中失衡阈值为 0 的角色跳过失衡积累

## 2. 当前生命与伤害扣除

### 2.1 MaxHP 变化时怎样调整当前生命

角色首次创建时取 `CurrentHP = MaxHP`，之后收到 MaxHP 变化，取 `CurrentHP = min(原 CurrentHP, 新 MaxHP)`

上限增加时保留已持有的生命点数，上限降低时只裁掉超出的点数，反复穿脱木剑或在 HP 为 0 时提高上限，均不会凭空恢复生命

以菲比连续受击、换装和治疗为例，她的 WIL 50 对应 5% 受治疗效率，治疗结算方将基础治疗量 40 算成 `40 × 1.05 = 42`，Resources 应用传入的 42

| 操作 | 属性页 MaxHP | 血条 CurrentHP / MaxHP | 本次结果 |
| --- | ---: | ---: | --- |
| 菲比进场 | 150 | 150 / 150 | 从最终面板初始化 |
| 应用已结算伤害 40 | 150 | 110 / 150 | 实际扣血 40，血条填充约 73.3% |
| 装备木剑，STR 从 10 升到 13 | 165 | 110 / 165 | 只改变分母，填充约 66.7% |
| 应用已结算治疗 42 | 165 | 152 / 165 | 实际恢复 42 |
| 卸下木剑 | 150 | 150 / 150 | 当前生命与上限在同一次资源通知中改变 |
| 满血时再次治疗 42 | 150 | 150 / 150 | 实际恢复 0，无资源变化通知 |

MaxHP 可以合法降为 0，对应读数为 `0 / 0`，血条填充为 0，之后 MaxHP 从 0 回到 150，读数为 `0 / 150`

Actors 根据生命变化决定倒下、可选目标及能否接受治疗，Resources 的 `RestoreHP` 对调用方已准许的治疗统一按剩余容量恢复

### 2.2 一次受击如何扣除 HP

Damage 完成防御和抗性结算后，将最终伤害 `finalDamage` 传给 `ApplyDamage`，Resources 直接从当前生命扣除，返回实际扣血量 `HPLost = min(受击前的 CurrentHP, finalDamage)` 和溢出量 `Overkill = finalDamage − HPLost`

以菲比剩余 90 HP 时连续受击两次为例

| 最终伤害 | 受击前 HP | 受击后 HP | 实际扣血 HPLost | 溢出 Overkill |
| ---: | ---: | ---: | ---: | ---: |
| 32 | 90 | 58 | 32 | 0 |
| 100 | 58 | 0 | 58 | 42 |

## 3. SP、终结技能量与失衡

| 操作 | 提交规则 | 可复算示例 |
| --- | --- | --- |
| 消耗 SP 或终结能量 | Skills 在确认技能提交的时点向所属池同步扣费一次，余额足够时全额扣除并返回 `true`，不足返回 `false` 并保留余额 | 队伍初始 SP 60，菲比消耗 40 成功，祀紧接着消耗 40 失败，两人查询同一余额 20，随后恢复 90，封顶至 100，实际恢复 80 |
| 获取终结能量 | 恢复入口按剩余容量封顶，返回实际增加量，切换角色保留各自能量 | 菲比为 90/100，祀为 30/80，给菲比 25 后得到 100/100，实际增加 10<br>菲比消耗 100 后为 0/100，祀仍为 30/80 |
| 累积失衡 | `新值 = Math.Clamp(原值 + 输入量, 0, 阈值)`，只在「未满 → 达到正阈值」的这一次返回 `true`，满槽后由 Status 在玩法指定的时点清零 | 目标 80/100，提交 35 后达到 100，返回 `true`，再次提交 10 返回 `false`，仍为 100，清零后再次填满可重触发<br>阈值为 0 时始终返回 `false`，读数维持 0 |

SP 回复速度、终结能量获取条件、失衡持续时间由对应玩法决定，例如周期回技力的效果在自己的战斗时间回调中向 SP 池提交恢复量

## 4. 公开接口与运行流程

### 4.1 公开接口

角色数值和队伍 SP 各有只读视图，HUD 从视图读取快照和订阅变化

| 类型 | 成员 | 调用者可观察到的结果 |
| --- | --- | --- |
| `IReadOnlyCharacterResources` | `CharacterResourceSnapshot Snapshot`，`Subscribe(Action<CharacterResourceSnapshot, CharacterResourceSnapshot>) → IDisposable` | 一次读取同一角色的 CurrentHP、MaxHP、UltimateEnergy、MaxUltimateEnergy、Stagger、StaggerThreshold，回调参数依次为旧、新快照 |
| `CharacterResourceContainer` | `ApplyDamage(double finalDamage) → HealthLossResult`，`RestoreHP(double finalHealing) → double` | 伤害返回实际扣血量 `HPLost` 和溢出量 `Overkill`，治疗返回实际恢复量 |
| `CharacterResourceContainer` | `TryConsumeUltimate(double cost) → bool`，`RestoreUltimate(double amount) → double` | 同步扣除或返回实际恢复量 |
| `CharacterResourceContainer` | `AddStagger(double amount) → bool`，`ResetStagger()` | 返回本次是否从未满变为满槽，重置只清积累值 |
| `IReadOnlySkillPoints` | `SkillPointSnapshot Snapshot`，`Subscribe(Action<SkillPointSnapshot, SkillPointSnapshot>) → IDisposable` | 快照只含该队伍的 CurrentSP、MaxSP，切换角色不产生 SP 变化事件 |
| `SkillPointPool` | `TryConsume(double cost) → bool`，`Restore(double amount) → double` | 执行队伍 SP 的同步消费与恢复 |

写入口在 Unity 主线程执行，点数必须有限且非负

非法点数在写入前抛出 `ArgumentOutOfRangeException`，保留原状态

零消耗返回成功，零恢复返回 0，零伤害返回 `(HPLost: 0, Overkill: 0)`，数值未变时均不通知

### 4.2 初始化、通知与销毁

**公共模块接入**　角色容器和队伍 SP 池直接调用 `NumericValidation.RequireFiniteInRange` 校验点数，用 `Math.Clamp` 为资源恢复和失衡累积封顶。两者各自持有公共通知器，在资源值发生变化时向 HUD 等订阅者发布旧、新两个快照 · [Common 详细设计](./Common%20公共模块详细设计.md)

1. **进场**　两份角色 Prefab 的 `CharacterStats` 同节点均挂有 `CharacterResources`，其 `Awake` 执行顺序为 −50，使用已创建的 `IReadOnlyStatSet` 和角色配置创建容器

   容器读取初始 MaxHP，订阅属性变化并保存订阅句柄，纯数值测试也从这个入口创建容器 · [菲比 Prefab](../Assets/Prefabs/Characters/Phoebe.prefab) · [祀 Prefab](../Assets/Prefabs/Characters/Si.prefab)
2. **上限联动**　容器在 Stats 的一批 `StatChange` 中查找 `StatId.MaxHP`，取其 `NewValue`，按第 2.1 节同时提交上限和当前值，快照保留最近一次同步的上限，供调用方一次读取配对的分子、分母
3. **变化通知**　每次写入先保存旧快照，完成全部变更后发布新快照，回调内读取 `Snapshot` 应等于新快照

   一次受击实际扣血时通知一次，因 MaxHP 下降而同时调整上限和当前 HP 时也只通知一次

   订阅回调用于观察结果，后续玩法写入放在本次调用返回后处理
4. **显示与角色切换**　`HealthHud` 在启用或调用 `Bind(CharacterResources)` 时先解除旧订阅，读取目标的完整快照并订阅变化，文字按 `0.## / 0.##` 格式显示两项点数，填充取 `MaxHP > 0 ? CurrentHP / MaxHP : 0`

   关闭 HUD 时解除该订阅，重新打开立即显示最新快照，角色属性页独立开关，从 Stats 读取 MaxHP · [角色属性面板](../Assets/Scripts/Runtime/UI/CharacterStatsPanel.cs)
5. **角色生命周期**　角色临时禁用或切走时保留其容器及 MaxHP 订阅，切回时沿用该角色的 HP、终结技能量和失衡积累值

   销毁角色时由 `CharacterResources.OnDestroy` 调用 `CharacterResourceContainer.Dispose()` 释放 Stats 订阅，下一场按配置初始化角色和队伍 SP 池
