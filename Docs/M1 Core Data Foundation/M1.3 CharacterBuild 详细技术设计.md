## 2. 配置与等级成长

### 2.1 Inspector 填什么

| 配置类型 | 字段 | 填写与读取规则 |
| --- | --- | --- |
| `CharacterBuildProfile` | `initialLevel`、`maxLevel`、`growthPerLevel[]` | 一级为现有角色初值，每条成长填写一个 `StatId` 和每级增量 `double`，等级使用整数，范围为 `[1, maxLevel]` |
| `CharacterBuildProfile` | `initialWeapon`、`initialGear`、`initialTalents[]` | 首版采用一个武器槽、一个装备槽和可同时启用的多个被动天赋，空槽贡献为零，同一天赋资产只生效一份 |
| `BuildModifierProfile` | `kind`、`entries[]` | 武器、装备、天赋共用一种词条资产，由 `Weapon / Gear / Talent` 区分用途，Inspector 直接配置 `StatModifier` 的 `statId`、`operation`、`value`、`priority` · [Stats 词条定义](../../Assets/Scripts/Runtime/Stats/Modifiers/StatModifier.cs) |

| 资产 | 配置的词条 | 菲比 1 级装备或启用后的单项变化 |
| --- | --- | --- |
| [木剑](../Assets/ScriptObjects/CharacterBuild/WoodenSword.asset) | `WeaponATK Flat +3`、`STR Flat +3` | 武器攻击 200 → 203，力量 10 → 13 |
| [护符](../Assets/ScriptObjects/CharacterBuild/GuardCharm.asset) | `BaseDEF Flat +8` | 最终防御 100 → 108 |

### 2.2 一次等级变化怎样结算

每条等级词条的值为 `(目标等级 − 1) × 每级增量`，以 `Flat` 提交到对应属性，1 级的成长贡献为空，因为每次都从目标等级计算，直接从 1 级设为 3 级与分两次升级应得到同一结果

下表以每级 STR +2、BaseHP +10 作为菲比的验收配置，主副能力系数和 MaxHP 公式沿用 Stats

| 菲比的构筑 | STR | BaseHP | WeaponATK | 最终 ATK | MaxHP |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 级，空手 | 10 | 100 | 200 | 704 | 150 |
| 2 级，空手 | 12 | 110 | 200 | 704 | 170 |
| 2 级，木剑 | 15 | 110 | 203 | 710.24 | 185 |
| 3 级，木剑 | 17 | 120 | 203 | 710.24 | 205 |
| 回到 1 级，保留木剑 | 13 | 100 | 203 | 710.24 | 165 |

2 级持木剑时，MaxHP 为 `110 + 15 × 5 = 185`，菲比的主副能力保持原值，最终 ATK 为 `((100 + 203) × 1.30 + 50) × 1.60 = 710.24`，两个数值均由 Stats 计算 · [Stats 计算器](../Assets/Scripts/Runtime/Stats/Calculation/StatCalculator.cs)

## 3. 换装、天赋与来源提交

### 3.1 一次换装只提交一次面板

CharacterBuild 为每个槽位及天赋保留资产引用，向 Stats 提交时使用一个来源键 `new SourceID("CharacterBuild", 0)`，每个角色持有独立的 `StatSet`，相同的键只覆盖本角色上一版构筑

既有用例中的 `Equipment/17` 是直接写 Stats 的演示来源，实际穿木剑时，两条木剑词条只经构筑来源提交一次 · [现有木剑用例](../Assets/Scripts/Test/Editor/Stats/StatSystemTests.cs)

1. 从当前选择生成候选构筑，只修改请求指定的等级、槽位或天赋，替换占用的槽位时，候选构筑直接持有新物品
2. 按等级成长、武器、装备、已启用天赋的顺序收集候选词条，保留天赋启用顺序及各资产内的词条顺序，将每条的操作、数值和优先级原样交给 Stats
3. 调用一次 `StatSet.ReplaceSource(buildSource, entries)`，集合为空时，现有接口会撤销整个构筑来源，其他模块提交的来源继续参与计算
4. `StatWriteResult.Success` 为真时保存候选选择，为假时保留旧选择并把具体错误返回调用方，失败请求保留旧面板和当前 HP，成功请求只在最终属性变化时发布一批通知 · [写入结果与只读接口](../Assets/Scripts/Runtime/Stats/Runtime/StatReadModels.cs)

**为什么要整组替换**　菲比带木剑满血进场为 `165 / 165`，换成提供 STR +5 的练习剑时应直接得到 `165 / 175`

若先卸木剑再装练习剑，Resources 会在中途把 HP 裁至 150，换完后只剩 `150 / 175`，一次替换才让资源订阅者只看到最终上限 · [资源容器的上限处理](../Assets/Scripts/Runtime/Resources/Character/CharacterResourceContainer.cs)

### 3.2 成功、重复请求与失败

| 请求 | 调用方应观察到的结果 |
| --- | --- |
| 换掉同槽物品或卸下物品 | 该槽贡献替换为新物品的词条，卸下时该槽贡献归零，等级、其他槽位和天赋继续生效 |
| 重复装备当前物品、重复设置当前等级或天赋开关 | 返回成功，面板和资源均无变化通知，两件数值相同的不同物品互换时，槽位查询返回新物品 |
| 切走角色、临时禁用再启用 | 等级、装备、天赋及当前 HP 保留在原角色实例上，销毁并重新创建该角色时再读取进场配置 |
| 设置越界等级、把天赋装进武器槽 | 返回失败，指出等级范围或不匹配的槽位，配置和调用共用相同的构筑规则 |
| 新词条与已有来源的同优先级 Override 冲突，或数值计算溢出 | 透传 Stats 的错误，保留此前生效的构筑，修正请求后可直接重试 |

## 4. 公开接口与运行流程

### 4.1 调用入口

写操作在 Unity 主线程同步完成，调用方通过返回值判断穿戴、卸下或升级是否成功 · [角色组件](../Assets/Scripts/Runtime/CharacterBuild/CharacterBuildComponent.cs) · [构筑状态与写入接口](../Assets/Scripts/Runtime/CharacterBuild/CharacterBuildState.cs)

| 类型 | 成员 | 用法 |
| --- | --- | --- |
| `CharacterBuildComponent` | `CharacterBuildState State { get; }` | 从目标角色逻辑根取得其独立构筑，组件引用 `CharacterBuildProfile` 并要求同节点存在 `CharacterStats` |
| `CharacterBuildState` | `static CharacterBuildState Create(StatSet stats, CharacterBuildProfile profile)` | 在传入的面板上应用进场构筑并返回状态，配置错误时抛出含资产名和原因的 `InvalidOperationException`，组件仅在成功时公开 `State` |
| `CharacterBuildState` | `int Level { get; }`、`BuildModifierProfile GetEquipped(BuildSlot slot)`、`bool IsTalentEnabled(BuildModifierProfile talent)` | 查询已提交的等级、槽内资产或天赋开关，空槽返回 `null` |
| `CharacterBuildState` | `bool TrySetLevel(int level, out string error)` | 设置目标等级，重算该等级的全部成长贡献 |
| `CharacterBuildState` | `bool TryEquip(BuildSlot slot, BuildModifierProfile item, out string error)` | `BuildSlot` 首版取 `Weapon` 或 `Gear`，传入物品时穿戴或替换，传入 `null` 时卸下 |
| `CharacterBuildState` | `bool TrySetTalentEnabled(BuildModifierProfile talent, bool enabled, out string error)` | 启用或撤销指定被动天赋，其他天赋保留 |

三种写操作成功时 `error` 为空，失败时给出具体的构筑配置错误或 Stats 返回的原因

Stats 在写入返回前同步通知属性页和资源订阅者，订阅回调读取该批最终数值，需要确认槽位或等级的调用方，在构筑命令返回后查询 `State`
