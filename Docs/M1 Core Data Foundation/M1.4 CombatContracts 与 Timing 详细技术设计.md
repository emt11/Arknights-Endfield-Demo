## 2. CombatContracts 怎样描述一次命中

### 2.1 哪些标识能作为同一次命中的依据

| 类型 | 字段 | 生成位置与有效范围 |
| --- | --- | --- |
| `ActorId` | `uint Value` | Actors 在单位进入本次战斗时分配，从 1 开始，场内不复用<br>切换操控角色保留其 ID，销毁后重新生成的单位取得新 ID |
| `AttackId` | `ActorId Attacker`、`uint Sequence` | Actions 每成功提交一次攻击，为该攻击者取下一个序号，从 1 开始<br>一次攻击的全部命中窗口共享该值，取消后重新出招取得新序号 |
| `HitWindowId` | `uint Value` | 由招式配置标识本次攻击内的一段命中窗口，从 1 开始<br>同一窗口横跨多个渲染帧时保持原值，第二段可再次命中的窗口使用另一个值 |

三个标识均为只读值类型，按字段比较相等并计算哈希，0 表示尚未分配，标识的有效范围为当前战斗

M1.4 用例直接给定序号，正式分配逻辑由 Actors 和 Actions 接入

**去重示例**　HitDetection 以 `(hit.Attack, hit.Window, hit.Target)` 为键，检查祀的第 7 次攻击

- 第 1 窗口连续两帧扫到菲比，或同时扫到菲比的两个碰撞体，只产生一次命中
- 第 2 窗口再次扫到菲比，或第 1 窗口扫到另一个目标，均产生新的命中
- 窗口关闭时由 HitDetection 释放该窗口的命中记录

### 2.2 从命中到扣血，什么时候可以发布事实

| 契约 | 字段 | 写入者与读取者 |
| --- | --- | --- |
| `HitContext` | `AttackId Attack`、`HitWindowId Window`、`ActorId Target`、`Vector3 WorldPoint`、`double BattleTime` | HitDetection 在筛选和去重通过后记录世界坐标与命中时的战斗秒数<br>Damage 从 `Attack.Attacker` 和 `Target` 取得交互双方，表现可读取接触点 |
| `DamageApplied` | `ActorId Source`、`ActorId Target`、`double BattleTime`、`double HPLost`、`double Overkill` | Damage 在资源提交返回后，复制双方 ID、实际扣血结果和提交时的战斗秒数<br>Presentation 从事实中取得指定角色的 ID，请求局部顿帧 |

以满血菲比为目标，假设祀这一击的最终伤害为 190

1. HitDetection 把本次 `HitContext` 交给 Damage，时间戳取自 `clock.Battle.Elapsed`
2. Damage 调用目标的 `ApplyDamage(190)`，菲比从 150 HP 降到 0，返回 `HPLost = 150`、`Overkill = 40`
3. 当 `HPLost > 0` 时，Damage 发布一条 `DamageApplied`，监听器此时已经能读到 HP 0，本例只对受击者调用 `clock.TryRequestHitStop(fact.Target, 0.030)`，下一次推进时菲比和祀得到不同的动作增量
4. 再对 0 HP 的菲比提交 20 点伤害，Resources 返回 `(0, 20)`，累计仍只有一条 HP 扣减事实 · [菲比初始生命验收](./M1.3%20CharacterBuild%20详细技术设计.md#阶段验收记录) · [Resources 的受击规则](./M1.2%20Resources%20详细技术设计.md#22-一次受击如何扣除-hp)

## 3. Timing 怎样推进一帧

### 3.1 四种时间分别给谁用

只读值 `TimeStep` 提供 `double Delta`（刚完成的一帧推进量）与 `double Elapsed`（累计量），统一使用秒，同一帧可反复读取

| 时间 | 一帧怎样推进 | 谁读取 |
| --- | --- | --- |
| Real | 驱动传入的未缩放帧间隔，战斗暂停时照常累计 | 暂停菜单、需要在暂停中继续的 UI |
| Battle | 战斗暂停取 0，其余帧取 `Real.Delta × BattleRate` | Effects 的持续时间与周期、战斗事实时间戳 |
| Presentation | 首版与 Battle 使用相同增量和累计值，局部顿帧只影响指定角色 | 战场火花等独立特效，绑定动作进度的刀光改读持有者的 Action |
| Action | 每名角色独立，先扣掉该角色本帧被冻结的真实秒数，再对余下时间应用 `BattleRate` | Actions 的时间轴、命中窗口、Animation 的角色动画图 |

新会话从 0 秒开始，默认正常速度 1，暂停是独立开关，恢复时沿用先前设置的倍率

角色注册时动作累计从 0 开始，切换操控权保留其时钟，每个招式自己的播放游标在招式开始时由 Actions 初始化

### 3.2 顿帧如何跨越暂停和慢速

对角色调用 `TryRequestHitStop(actor, seconds)` 时，剩余时长取 `max(原剩余量, seconds)`，顿帧以**未暂停的真实秒数**计量，全局暂停保留剩余量，慢速只影响解除顿帧后可推进的动作量

每次 `Advance(realDelta)` 先确定本帧可用于战斗的真实时间，再为每个角色结算一次

```text
可用真实时间 = 战斗暂停时取 0，否则取 realDelta
战斗增量     = 可用真实时间 × 战斗倍率
本帧冻结量   = min(该角色剩余顿帧, 可用真实时间)
角色动作增量 = (可用真实时间 − 本帧冻结量) × 战斗倍率
剩余顿帧     = 该角色剩余顿帧 − 本帧冻结量
```

两名角色从同一帧开始计时，各行连续执行，控制请求在该行推进前提交，表中时间单位为 ms

| 帧前操作 | 真实增量 | 战斗增量 | 表现增量 | 菲比动作增量 | 祀动作增量 | 菲比剩余顿帧 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 正常速度 | 16 | 16 | 16 | 16 | 16 | 0 |
| 给菲比请求 30 ms 顿帧 | 20 | 20 | 20 | 0 | 20 | 10 |
| 设置半速并暂停战斗 | 100 | 0 | 0 | 0 | 0 | 10 |
| 解除暂停，以半速继续 | 16 | 8 | 8 | 3 | 8 | 0 |
| 保持半速 | 20 | 10 | 10 | 10 | 10 | 0 |
| **最终累计** | **172** | **54** | **54** | **29** | **54** | **0** |

恢复帧的 16 ms 中，前 10 ms 用完菲比的顿帧，余下 6 ms 以半速推进 3 ms

若在本帧动作或命中处理期间才收到顿帧请求，从下一次 `Advance` 开始扣时，保证本帧先读动作窗口或先更新动画都能得到相同增量

## 4. 公开接口与运行流程

### 4.1 调用入口

CombatContracts 仅依赖基础值类型和表示世界坐标的 `Vector3`，Timing 使用 `ActorId` 和 Common 的数值校验，依赖方向为 `Timing → CombatContracts`

| 类型 | 公开成员 | 行为 |
| --- | --- | --- |
| `BattleClock` | `TimeStep Real / Battle / Presentation { get; }` | 返回最近一次推进的各域读数，首次推进前增量与累计量均为 0 |
| `BattleClock` | `void Advance(double realDelta)` | 一次提交全局和所有已注册角色的时间步<br>场景中由唯一的驱动调用，纯 C# 用例可直接输入指定步长 |
| `BattleClock` | `void SetPaused(bool paused)`、`void SetBattleRate(double rate)` | 设定下一次推进使用的暂停状态和正的有限倍率，半速填 0.5 |
| `BattleClock` | `bool RegisterActor(ActorId actor)`、`bool UnregisterActor(ActorId actor)` | 首次登记有效 ID 或成功移除返回 true<br>未分配的 ID、重复登记或移除不存在的角色返回 false<br>重复登记保留已有动作时间，成功移除时一并丢弃剩余顿帧 |
| `BattleClock` | `bool TryGetActionTime(ActorId actor, out TimeStep step)`、`bool TryRequestHitStop(ActorId actor, double seconds)` | 对已登记角色读取本帧时间或提交顿帧，角色已离场时返回 false<br>请求 0 秒保留已有顿帧 |
| `BattleClock` | `IDisposable SubscribeBattleStep(Action<TimeStep> listener)` | 各时间域提交后，同步发布本步 `Battle`；角色效果订阅一次，离场时释放订阅 |
| `BattleTimeDriver` | `BattleClock Clock { get; }` | `Awake` 创建本场时钟，`Update` 采样一次 `Time.unscaledDeltaTime` 后推进，使用组件执行顺序让它先于默认顺序的玩法消费者运行 · [Unity 帧间隔](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Time-unscaledDeltaTime.html) |

`realDelta` 和顿帧时长接受非负有限秒数，负数和非有限值在写入前通过 `NumericValidation.RequireFiniteInRange` 拒绝，非法倍率同样在提交前报告参数错误

0 秒步长产生零增量，保留所有累计值和剩余顿帧 · [共用数值校验](../../Assets/Scripts/Runtime/Common/NumericValidation.cs)

### 4.2 从场景取时到动画求值

1. **开场**　`CombatDemo` 加载时驱动在 `Awake`（顺序 −200）创建时钟，角色效果在 `Start` 订阅本场战斗步。动作时间按角色登记，双角色原型在测试中提供 ID
2. **取时**　驱动在 `Update` 推进时钟，随后 Effects 和角色消费者各自读取时间，战斗暂停期间驱动继续采样 Real，局部顿帧只更新指定角色的记录，项目的 `Time.timeScale` 沿用工程设置 · [当前时间设置](../../ProjectSettings/TimeManager.asset)
3. **推进窗口和动画**　Actions 用 `step.Delta` 推进窗口，动画原型为每个角色各建一张手动求值的图，只用该角色的增量调用 `graph.Evaluate((float)step.Delta)`，图以速度 1 播放，初始姿态用 `Evaluate(0f)` 采样，后续零增量帧保留已采样姿态 · [Unity 手动更新模式](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Playables.DirectorUpdateMode.Manual.html) · [Unity 图求值](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Playables.PlayableGraph.Evaluate.html)
4. **离场**　切换操控角色保留双方时钟，角色销毁时移除登记并由动画图的创建者销毁图，重新开场时创建新时钟，清除上一场的暂停、倍率与顿帧状态

本阶段用双角色原型验证 `DirectorUpdateMode.Manual`，动作游标、片段时间和实际骨骼姿态均符合第 5 节预期后，再将该模式记入 M5 Animation Foundation 的接入依据
